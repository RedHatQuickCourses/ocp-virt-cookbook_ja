AI エージェントワークフローによる VM スナップショット管理

このチュートリアルでは、4 つのエージェントスキル (vm-snapshot-create、vm-snapshot-list、vm-snapshot-restore、vm-snapshot-delete) を通じて自然言語コマンドを使用し、仮想マシンスナップショットの完全なライフサイクルを管理する方法を説明します。アップグレード前のスナップショットの作成、利用可能なスナップショットの一覧表示、アップグレード失敗後のリストア、リストアされた VM の検証、古いスナップショットのクリーンアップという現実的なシナリオを一通り行います。

前提条件

  • AI エージェントによる VM 管理の開始 チュートリアルを完了していること (スキルパックがインストール済み、MCP サーバーが設定済み、クラスターへの接続が確認済み)

  • OpenShift Virtualization がインストールされた OpenShift クラスター

  • KUBECONFIG 環境変数が設定され、有効な kubeconfig ファイルを指していること

  • 管理対象となる 1 つ以上の VM (作成するには 自然言語による仮想マシンの作成 を参照)

  • CSI スナップショットをサポートするストレージバックエンド (ストレージプロビジョナー用の VolumeSnapshotClass が存在する必要があります)

  • VirtualMachineSnapshot および VirtualMachineRestore リソースを作成、一覧表示、削除するための RBAC 権限

このチュートリアルで使用する namespace がまだ存在しない場合は、作成します。

oc create namespace my-vms

管理対象の VM がない場合は、IDE チャットで次のように入力し、vm-create スキルを使用して作成します。

Create a Fedora VM named database-01 in namespace my-vms

続行する前に、VM が存在することを確認します。

oc get vm -n my-vms

想定される出力:

NAME     AGE  STATUS  READY
database-01  5m  Running  True

ストレージバックエンドがスナップショットをサポートしていることを確認します。

oc get volumesnapshotclass

想定される出力 (ドライバー名およびクラス名は異なる場合があります):

NAME       DRIVER    DELETIONPOLICY  AGE
lvms-snapclass  topolvm.io  Delete      17d

VolumeSnapshotClass が返されない場合は、続行する前にクラスター管理者に連絡して設定してください。

動作の仕組み

4 つのスナップショットスキルは、スナップショットのライフサイクル全体をカバーします。各スキルは、データを変更または破棄する操作の前に、Human-in-the-loop (人間による確認) を強制します。

vm-snapshot-create スキル

vm-snapshot-create スキルは、複数のステップからなるワークフローに従います。

  1. VM の検証とストレージの分析 — エージェントは VM が存在することを確認し、ホットプラグされたボリューム (スナップショットをブロックします) をチェックし、StorageClass が CSI スナップショットをサポートしていることを検証して、一致する VolumeSnapshotClass を特定します。

  2. VM の状態とゲストエージェントの確認 — エージェントは VM が実行中か停止しているかを判別します。ストレージバックエンドがオンラインスナップショットをサポートしている場合、エージェントは QEMU guest agent が接続されているかどうかを報告します。ゲストエージェントが接続されていると、ファイルシステムのフリーズ/復帰 (freeze/thaw) を通じてアプリケーション整合性のあるスナップショットが可能になります。接続されていない場合、スナップショットはクラッシュ整合性となります。

  3. ストレージの見積もりと設定の提示 — エージェントはストレージ消費量を見積もり、適用される正確な YAML を表示して、明示的な確認を待ちます。

  4. 作成と監視 — 確認後、エージェントは VirtualMachineSnapshot リソースを作成し、そのステータスが Succeeded または Failed になるまで監視します。

vm-snapshot-list スキル

vm-snapshot-list スキルは、確認を必要としない読み取り専用の操作です。 namespace 内のすべてのスナップショットを一覧表示し (オプションで VM 名によるフィルタリングが可能)、各スナップショットのステータス、経過時間、復元の準備状態を表示します。

vm-snapshot-restore スキル

vm-snapshot-restore スキルは、スナップショットスキルの中で最も厳格な安全モデルを適用します。

  1. VM が停止していることの確認 — 実行中の VM を復元するとデータの破損につながります。VM が実行中の場合、エージェントは最初に VM を停止するかキャンセルするかを提案します。

  2. スナップショットの準備完了の確認 — エージェントはスナップショットが存在し、readyToUse: true であることを確認します。

  3. 入力によるスナップショット名の確認 — 確認のために正確なスナップショット名を入力する必要があります。一致しない場合、操作はキャンセルされます。

  4. 最終的な yes/cancel の確認 — 入力による検証に合格した後、エージェントは実行前にもう一度確認します。

  5. 実行と監視 — エージェントは VirtualMachineRestore リソースを作成し、リストアが完了するまで進捗を監視します。

vm-snapshot-delete スキル

vm-snapshot-delete スキルは、スナップショットを完全に削除してそのストレージを解放します。

  1. スナップショットの存在確認 — エージェントはスナップショットの詳細を取得し、同じ VM の他のスナップショットを一覧表示します。

  2. 最後のスナップショットの場合の警告 — これが仮想マシンの唯一のスナップショットである場合、エージェントは復元ポイントが残らないという警告を表示します。

  3. スナップショット名の入力による確認 — 削除を確認するには、正確なスナップショット名を入力する必要があります。

  4. 削除とレポート — エージェントはスナップショットを削除し、残りのスナップショットとともに結果をレポートします。

スナップショットの一貫性レベル

スナップショットの一貫性は、VM が実行中であるかどうか、および QEMU guest agent がアクティブであるかどうかによって異なります。

VM の状態 ゲストエージェント 一貫性レベル

Stopped

N/A

オフラインスナップショット — 完全に一貫性があり、正常なシャットダウンと同等

Running

Connected

アプリケーション整合性あり — スナップショットの作成中にゲストエージェントがファイルシステムを凍結

Running

Not connected

クラッシュ整合性 — 電源コードを抜いた状態と同等。使用可能ですが、リストア時にファイルシステムのリカバリーが必要になる場合があります

実稼働 VM の場合、アプリケーション整合性のあるキャプチャーを確保するために、スナップショットを作成する前に QEMU guest agent をインストールしてください。Linux VM の場合:

sudo dnf install qemu-guest-agent
sudo systemctl enable --now qemu-guest-agent

Windows VM の場合は、ゲストエージェントが含まれ、Windows ワークロードのアプリケーション整合性スナップショットに対応する VSS (Volume Shadow Copy Service) をサポートしている VirtIO ドライバーパッケージをインストールします。

このシナリオでは、VM 上のアプリケーションソフトウェアをアップグレードする前にスナップショットを作成する方法を説明します。スナップショットは、アップグレードが失敗した場合のロールバックポイントとして機能します。

    Create a snapshot of database-01 before I upgrade it

    my-vms

エンドツーエンドのシナリオ: アップグレード前のバックアップとリカバリー

本セクションでは、上記のシナリオで実践した一連のワークフローをまとめています。本番環境の VM でアップグレードを実行する際の参照チェックリストとして使用してください。

  1. アップグレード前のスナップショットを作成する — アップグレードを開始する前に、ロールバックポイントとしてスナップショットを作成します。

    Create a snapshot of database-01 in namespace my-vms

  2. アップグレードを実行する — アップグレード手順を実行します (パッケージのインストール、設定の更新、移行の実行など)。

  3. アップグレードを検証する — アプリケーションをテストして、アップグレードが成功したことを確認します。

  4. アップグレードが成功した場合 — ストレージを解放するために、アップグレード前のスナップショットを削除します。

    Delete snapshot database-01-snapshot-20260714-100000 in namespace my-vms

  5. アップグレードに失敗した場合 — アップグレード前のスナップショットから VM を復元します。

    Restore database-01 from snapshot database-01-snapshot-20260714-100000

  6. 復元した VM の起動 — 復元が完了したら、VM を起動して正常であることを確認します。

    Start VM database-01 in namespace my-vms

  7. 古いスナップショットのクリーンアップ — 復元した VM が正常であることを確認した後、不要になったスナップショットを削除します。

    List snapshots for VM database-01 in namespace my-vms

ホットプラグされたボリュームの制限

ホットプラグされたボリューム (VM の作成後に再起動なしでアタッチされたボリューム) を持つ VM はスナップショットを作成できません。ホットプラグされたボリュームを持つ VM のスナップショットを作成しようとすると、エージェントはエラーを報告し、解決手順を提案します。

  1. VM を停止して、ホットプラグされたボリュームをデタッチします。

  2. ボリュームがホットプラグされたものとみなされなくなるよう、VM spec 内でボリュームを永続化します。

  3. VM を再起動します。

  4. スナップショット操作を再試行します。

Human-in-the-Loop の確認

4 つのスナップショットスキルはすべて、意図しないデータの変更を防ぐ安全モデルを実施します。

読み取り専用操作 (vm-snapshot-list):

  • 確認は不要です。エージェントはスナップショットを一覧表示し、すぐに結果を報告します。

スナップショットの作成 (vm-snapshot-create):

  • エージェントは、設定を提示する前にストレージバックエンドとゲストエージェントのステータスを分析します。

  • 適用される正確な YAML が確認用に表示されます。

  • スナップショットが作成される前に、"yes" で明示的に確認する必要があります。

スナップショットの復元 (vm-snapshot-restore):

  • 復元前に VM を停止する必要があります。実行中の場合、エージェントは停止を提案します。

  • 確認のために正確なスナップショット名 (大文字と小文字を区別) を入力する必要があります。

  • 入力による検証の後、もう一度 "yes" で確認する必要があります。

  • 不一致または "yes" 以外の応答があった場合、操作はキャンセルされます。

スナップショットの削除 (vm-snapshot-delete):

  • エージェントはスナップショットの詳細を表示し、同じ VM で利用可能な他のスナップショットを一覧表示します。

  • これがその VM の最後のスナップショットである場合、警告が表示されます。

  • 確認のため、正確なスナップショット名 (大文字と小文字を区別) を入力する必要があります。

  • 一致しない場合、操作はキャンセルされます。

一般的な問題

VolumeSnapshotClass が見つからない

エージェントが、お使いのストレージプロビジョナー用の VolumeSnapshotClass が存在しないと報告した場合、ストレージバックエンドがスナップショット用に設定されていない可能性があります。クラスター管理者に確認し、以下を実行して検証してください。

oc get volumesnapshotclass

クラッシュ整合性スナップショットの警告

エージェントがアプリケーション整合性ではなくクラッシュ整合性スナップショットを報告する場合、QEMU guest agent が VM 内で実行されていません。インストールして有効にしてください。

sudo dnf install qemu-guest-agent
sudo systemctl enable --now qemu-guest-agent

エージェントが接続されていることを確認します。

oc get vmi database-01 -n my-vms -o jsonpath='{.status.conditions[?(@.type=="AgentConnected")].status}'
True

復元が In Progress のまま停止する

復元操作が 10 分以上 InProgress 状態のままになっている場合は、VirtualMachineRestore リソースでエラー状態を確認してください。

oc get virtualmachinerestore -n my-vms -o yaml

一般的な原因としては、ストレージクォータの不足、CSI ドライバーの問題、破損したスナップショットなどが考えられます。問題が解決しない場合は、クラスター管理者に問い合わせてください。

クリーンアップ

このチュートリアルで作成したスナップショットを削除するには:

oc delete virtualmachinesnapshot --all -n my-vms

VM を削除するには:

oc delete vm database-01 -n my-vms

namespace を削除するには:

oc delete namespace my-vms

まとめ

  • vm-snapshot-create スキルは、ストレージバックエンドの完全な検証、ゲストエージェントの検出、実行前の確認を行って、特定時点のスナップショットを作成します。

  • vm-snapshot-list スキルは、確認を必要とせずにスナップショットをステータス、作成からの経過時間、準備状態とともに表示する読み取り専用の操作です。

  • vm-snapshot-restore スキルは最も厳格な安全モデルを適用します。リストアを実行する前に、VM が停止していること、スナップショット名を入力して確認すること、および最終的な yes/cancel による確認ゲートが必要です。

  • vm-snapshot-delete スキルでは名前の入力による確認が必要であり、VM の最後のスナップショットを削除する際に警告が表示されます。

  • アプリケーション整合性のあるスナップショットには、QEMU guest agent (Linux) または VSS サポート付きの VirtIO driver (Windows) がインストールされ、実行されている必要があります。

  • エンドツーエンドのアップグレード前ワークフローは、スナップショットの作成、アップグレードの実行、検証、そしてクリーンアップ (成功時) またはリストア (失敗時) のいずれかです。
