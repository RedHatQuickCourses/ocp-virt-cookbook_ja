QEMU guest agent のインストール

概要

このチュートリアルでは、さまざまな Linux ディストリビューションに qemu-guest-agent をインストールする方法を説明します。QEMU guest agent は、ゲスト OS 内で実行されるデーモンです。これにより、アプリケーション整合性のあるスナップショット、ゲスト OS、ファイルシステムのレポート、動的な SSH 鍵およびパスワードのインジェクション、IP アドレスのレポート、exec/ping ヘルスプローブなどが可能になります。

学習内容

  • Fedora、Debian、openSUSE Leap で virtctl console を使用して qemu-guest-agent を手動でインストールおよび有効化する方法

  • cloud-init の packages および runcmd モジュールを使用して qemu-guest-agent を自動的にインストールする方法

  • エージェントが接続され、ゲスト OS 情報を OpenShift Virtualization にレポートしていることを確認する方法

前提条件

  • OpenShift Virtualization Operator がインストールされた OpenShift 4.18+ (OpenShift Virtualization のインストール を参照)

  • CLI ツール: oc、virtctl、yq

namespace の設定

このチュートリアルで使用するすべての仮想マシンを配置する namespace を作成します。

oc create namespace qemu-ga-demo
oc project qemu-ga-demo

virtctl console を使用したインストール

このセクションでは、virtctl console <vm-name> を使用して仮想マシンのコンソールに接続し、cloud-init で作成されたユーザーとしてログインし、ディストリビューションのパッケージマネージャーを使用して qemu-guest-agent をインストールし、systemctl enable --now qemu-guest-agent を実行してサービスを起動するとともに再起動後も有効になるよう設定します。

以下の例で使用されている cloud-init のパスワードはデモ目的のみのものです。本番環境では、常に強力で一意のパスワードまたは SSH 鍵認証を使用してください。

Fedora/RHEL

ステップ 1: Fedora 仮想マシンの作成

CLI から仮想マシンを作成します。 (Web コンソールから作成する場合は こちら をクリック)

containerdisk の代わりに datavolume を使用しています。これにより初回の起動時間は長くなりますが、ルートボリュームが PVC に保存されるため、virt-launcher がクラッシュした場合や、仮想マシンを停止して再起動した場合でも、以降の手順での変更が永続化されるという利点があります。

fedora-no-qga.yaml のダウンロード

oc apply -f - <<EOF
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
 name: fedora-virtctl
 namespace: qemu-ga-demo
spec:
 runStrategy: Always
 dataVolumeTemplates:
  - metadata:
    name: fedora-virtctl-rootdisk
   spec:
    storage:
     resources:
      requests:
       storage: 10Gi
     accessModes:
      - ReadWriteOnce
    source:
     registry:
      url: docker://quay.io/ocpv_cookbook/fedora-no-qga:latest
 template:
  metadata:
   labels:
    app: fedora-virtctl
  spec:
   domain:
    cpu:
     cores: 2
    memory:
     guest: 4Gi
    devices:
     disks:
      - name: rootdisk
       disk:
        bus: virtio
      - name: cloudinitdisk
       disk:
        bus: virtio
   volumes:
    - name: rootdisk
     dataVolume:
      name: fedora-virtctl-rootdisk
    - name: cloudinitdisk
     cloudInitNoCloud:
      userData: |-
       #cloud-config
       user: fedora
       password: fedora
       chpasswd: { expire: false }
EOF

仮想マシンの STATUS が Running になるまで待ちます。

oc get vm fedora-virtctl -w
-w フラグは継続的に監視します。STATUS が Running と表示されたら Ctrl+C を押します。 
# 出力例
NAME        AGE  STATUS  READY
fedora-virtctl      6h8m  Running  True

ステップ 2 に進みます

Web コンソールから仮想マシンを作成します。

  1. Virtualization → VirtualMachines に移動します

  2. 右上にある Create ボタンの横のドロップダウンをクリックします

  3. With YAML を選択します

  4. テキストエディターウィンドウ内のすべてを選択して削除します

  5. 上記の YAML を貼り付けます

  6. 左下の Create をクリックします

新しく作成した VM の「Overview」タブにリダイレクトされます。Status が Running になるまで待ちます。

ステップ 2: qemu-guest-agent のインストールと有効化

CLI から: (Web コンソールの手順についてはこちらをクリック)

virtctl console fedora-virtctl

ログインプロンプトを表示するために ENTER キーを押す必要がある場合があります。表示されたら、ユーザー名とパスワードの両方に fedora を入力します。

次のステップに進みます

Web コンソールから:

  1. Virtualization → VirtualMachines に移動します。

  2. 仮想マシンの名前をクリックします

  3. overview タブの Details パネルで "Open Web Console" をクリックします (これにより新しいブラウザーウィンドウが開きます)

  4. ユーザー名に fedora と入力し、Enter キーを押します

  5. パスワードに fedora と入力し、Enter キーを押します

qemu-guest-agent がインストールされていないことを確認します。

systemctl status qemu-guest-agent
# 出力例
Unit qemu-guest-agent.service could not be found.

dnf を使用して qemu-guest-agent をインストールし、有効化します。

sudo dnf install -y qemu-guest-agent && sudo systemctl enable --now qemu-guest-agent

qemu-guest-agent がインストールされ、有効化され、実行されていることを確認します。

systemctl status qemu-guest-agent
# 出力例
[fedora@fedora-virtctl ~]$ systemctl status qemu-guest-agent
● qemu-guest-agent.service - QEMU Guest Agent
   Loaded: loaded (/usr/lib/systemd/system/qemu-guest-agent.service; enabled; preset: enabled)
  Drop-In: /usr/lib/systemd/system/service.d
       └─10-timeout-abort.conf
   Active: active (running) since Tue 2026-06-02 21:49:02 UTC; 8s ago # <-- Active (running) に注目
 Invocation: e1d60262b0cc499b967d42561a6e59ff
  Process: 1436 ExecStartPre=<<truncated>>
  Main PID: 1438 (qemu-ga)
   Tasks: 2 (limit: 4618)
   Memory: 996K (peak: 1.4M)
    CPU: 21ms
   CGroup: /system.slice/qemu-guest-agent.service
       └─1438 /usr/bin/qemu-ga --method=virtio-serial --path=/dev/virtio-ports/org.qemu.guest_agent.0 <<truncated>>

ctrl+] または ctrl+5 を使用して VM コンソールを終了します。

この VM に対して検証コマンドが機能するように VM_NAME 変数を設定します。

VM_NAME=fedora-virtctl

qemu-guest-agent が OCP-Virt にレポートしていることの確認 に進み、エージェントが接続され、OCP-Virt にレポートしていることを確認します。

cloud-init の packages および runcmd モジュールを使用したインストール

cloud-init の packages モジュールを使用すると、ブートプロセス中にパッケージをインストールできます。このセクションでは、これを使用して qemu-guest-agent パッケージをインストールします。インストールが完了すると、cloud-init の runcmd モジュールが systemctl enable --now qemu-guest-agent を実行し、ブート中にサービスを起動して有効化します。

以下の例の cloud-init パスワードはデモ目的専用です。本番環境では、常に強力で一意なパスワードまたは SSH 鍵認証を使用してください。

Fedora/RHEL

仮想マシンを作成します。

fedora-qga-package.yaml をダウンロード

oc apply -f - <<EOF
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
 name: fedora-cloudinit
 namespace: qemu-ga-demo
spec:
 runStrategy: Always
 dataVolumeTemplates:
  - metadata:
    name: fedora-cloudinit-rootdisk
   spec:
    storage:
     resources:
      requests:
       storage: 10Gi
     accessModes:
      - ReadWriteOnce
    source:
     registry:
      url: docker://quay.io/ocpv_cookbook/fedora-no-qga:latest
 template:
  metadata:
   labels:
    app: fedora-cloudinit
  spec:
   domain:
    cpu:
     cores: 2
    memory:
     guest: 4Gi
    devices:
     disks:
      - name: rootdisk
       disk:
        bus: virtio
      - name: cloudinitdisk
       disk:
        bus: virtio
   volumes:
    - name: rootdisk
     dataVolume:
      name: fedora-cloudinit-rootdisk
    - name: cloudinitdisk
     cloudInitNoCloud:
      userData: |-
       #cloud-config
       user: fedora
       password: fedora
       chpasswd: { expire: false }
       packages: (1)
        - qemu-guest-agent
       runcmd: (2)
        - systemctl enable --now qemu-guest-agent (3)
EOF
1 packages cloud-init モジュールを使用して qemu-guest-agent をインストールします
2 runcmd cloud-init モジュールを使用して起動中に任意のコマンドを実行します
3 パッケージのインストール後に systemctl enable --now qemu-guest-agent を実行してサービスを開始します

debian-qga-package.yaml のダウンロード

oc apply -f - <<EOF

kind: VirtualMachine
metadata:
 name: debian-cloudinit
 namespace: qemu-ga-demo

 runStrategy: Always
 dataVolumeTemplates:

    name: debian-cloudinit-rootdisk
   spec:

       storage: 10Gi

     registry:

qemu-guest-agent が OCP-Virt にレポートしていることの確認

Web コンソールから、または oc および virtctl CLI ツールを使用してターミナルから、qemu-guest-agent が動作し、ゲスト OS に関する情報を OCP-Virt に適切にレポートしているかを確認する方法はいくつかあります。

ターミナルからの確認

AgentConnected 条件が True であることを確認します。

oc get vm $VM_NAME -oyaml | yq -e '.status.conditions[] | select(.type == "AgentConnected")'

成功した場合の出力は次のようになります。

# 出力例
lastProbeTime: "2026-06-04T13:33:28Z"
lastTransitionTime: null
status: "True"
type: AgentConnected

guest-agent が VM の IP アドレスを報告していることを確認します。

oc get vmi $VM_NAME -oyaml | yq -e '.status.interfaces[]'
# 出力例
infoSource: domain, guest-agent (1)
interfaceName: enp1s0
ipAddress: 10.130.0.22
ipAddresses:
 - 10.130.0.22
linkState: up
mac: 0a:58:0a:82:00:16
name: default
podInterfaceName: eth0
queueCount: 1
1 infoSource として guest-agent が存在する場合、IP アドレスが qemu-guest-agent によって報告されていることを示します。

詳細なゲスト OS 情報を取得します。

virtctl guestosinfo $VM_NAME

OCP-Virt Web コンソールによる検証

  1. Virtualization → VirtualMachines に移動します。

  2. 仮想マシンをクリックします。

Overview タブで、qemu-guest-agent がゲスト OS 情報をレポートしていることを確認できます。

Diagnostics タブで、仮想マシンの AgentConnected の status が True になっていることを確認できます。
