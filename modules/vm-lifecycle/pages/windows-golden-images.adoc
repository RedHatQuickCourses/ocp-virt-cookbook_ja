= Windows ゴールデンイメージの作成
:navtitle: Windows ゴールデンイメージ

== 概要

このチュートリアルでは、`windows-efi-installer` Tekton パイプラインを使用して OpenShift Virtualization 上に Windows Server 2025 ゴールデンイメージを作成する手順を説明します。このパイプラインは、ISO のダウンロード、無人ブート用の変更、VirtIO ドライバーを使用したサイレントインストールの実行、sysprep によるイメージの汎用化といった一連のワークフロー全体を自動化します。完了すると、このゴールデンイメージから新しい Windows VM をデプロイでき、クローンごとのカスタマイズは sysprep の `unattend.xml` ファイルによって処理されます。

Windows には Linux の cloud-init に相当するものがないため、Windows ではパイプラインによるアプローチが必要です。代わりに、Windows では無人インストールに `autounattend.xml` を使用し、汎用化に sysprep を使用します。これらのステップを手動で自動化するとエラーが発生しやすいため、パイプラインが最初から最後まで一括して処理します。

== 学習内容

* Windows ゴールデンイメージと Linux ゴールデンイメージの違い
* Windows Server 2025 の無人インストールのために `autounattend.xml` を設定する方法
* ゴールデンイメージを構築するために `windows-efi-installer` Tekton パイプラインを実行する方法
* クローンごとの sysprep カスタマイズを行ってゴールデンイメージから VM をデプロイする方法
* 他の Windows バージョン (10、11、Server 2022) 向けにプロセスを適応させる方法

== Windows ゴールデンイメージと Linux の違い

Linux と Windows では、ゴールデンイメージワークフローの各段階で異なるメカニズムが使用されます。

[cols="1,1,1"]
|===
|段階 |Linux |Windows

|**無人インストール**
|Kickstart または preseed
|`autounattend.xml` (Windows セットアップ応答ファイル)

|**インストール後のカスタマイズ**
|初回起動時の cloud-init
|初回起動時の sysprep による `unattend.xml` (OOBE パス)

|**一般化**
|`/etc/machine-id` の削除、`cloud-init clean` の実行
|`sysprep /generalize /oobe /shutdown` の実行

|**クローンごとの個別設定**
|cloud-init `userData` (ホスト名、SSH 鍵、パッケージ)
|Sysprep `unattend.xml` ボリューム (ホスト名、管理者パスワード、RDP)

|**ドライバーの組み込み**
|通常はカーネルに含まれるドライバー
|インストール中に VirtIO ドライバーをロードする必要がある
|===

`windows-efi-installer` パイプラインは、これらのステップをすべて自動化します。ISO をダウンロードし、無人ブート用にブートローダーにパッチを適用し、空のディスクを作成し、`autounattend.xml` ConfigMap と VirtIO ドライバーコンテナディスクを使用してインストーラー VM を起動し、インストールと sysprep の完了を待機して、作成されたディスクを DataSource として公開します。

== 前提条件

* OpenShift Virtualization Operator がインストールされている OpenShift {ocp-min-version}+
* OpenShift Pipelines Operator がインストールされていること (Tekton を提供)
* CLI ツール: `oc` および `kubectl`
* link:https://www.microsoft.com/en-us/evalcenter/evaluate-windows-server-2025[Microsoft Evaluation Center,window=_blank] からの Windows Server 2025 評価版 ISO のダウンロード URL
* ルートディスク用に少なくとも 60 GiB を利用可能な Storage Class
* クラスターから `go.microsoft.com` (または内部 ISO ミラー) へのネットワークアクセス
* xref:custom-golden-images.adoc[Linux ゴールデンイメージワークフロー] に関する知識

== ステップ 1: Namespace と ServiceAccount の準備

パイプラインは `default` namespace で実行されます。`modify-windows-iso-file` パイプラインタスクがワークスペースボリュームに書き込みを行うには、特定のユーザー ID およびグループ ID が必要です。`pipeline` サービスアカウントに `anyuid` Security Context Constraint (SCC) を付与します。

[source,bash,role=execute]
----
oc adm policy add-scc-to-user anyuid -z pipeline -n default
----

これにより、ISO 変更ツールが必要とする `runAsUser: 107` および `fsGroup: 107` でタスク Pod を実行できるようになります。

=== autounattend.xml の処理内容

このファイルには 4 つの Windows セットアップパスが含まれています。

. **windowsPE** -- ファイルがディスクにコピーされる前の Windows プレインストール環境中に実行されます。インストーラーが VirtIO SCSI ディスクと NIC を認識できるように、VirtIO ストレージ (`viostor`) およびネットワーク (`NetKVM`) ドライバーをロードします。また、ディスクを GPT レイアウト (EFI、MSR、およびプライマリーパーティション) でパーティション分割し、Windows Server 2025 Datacenter (Desktop Experience) エディションを選択して EULA に同意します。
. **specialize** -- ファイルがディスクにコピーされた後に実行されます。地域と言語の設定を `en-US` に設定します。
. **oobeSystem** -- 通常、このパスでは Out-Of-Box Experience (OOBE) ウィザードが実行されます。ここでは代わりに監査モードにリシールするように設定されており、OOBE をスキップしてビルトイン Administrator としてデスクトップに直接起動するため、インストール後スクリプトを実行できます。
. **auditUser** -- 監査モードで実行されます。`post-install.ps1` を実行した後、`sysprep /generalize /oobe /shutdown` を呼び出してマシン固有の識別子を削除し、VM をシャットダウンします。結果として得られるディスクは、クリーンで汎用化されたゴールデンイメージになります。

=== post-install.ps1 の動作

この PowerShell スクリプトは監査モードで SYSTEM として実行され、4 つのタスクを実行します。

. `E:\` にマウントされた VirtIO コンテナディスクから VirtIO guest driver package (`virtio-win-gt-x64.msi`) をインストールします。
. デプロイ後に OpenShift が VM と通信できるように、QEMU guest agent (`qemu-ga-x86_64.msi`) をインストールします。
. キャッシュされた `C:\Windows\Panther\unattend.xml` を `unattend.install.xml` に名前変更します。これにより、クローンされた VM の初回起動時に sysprep がインストール時の応答ファイルを読み込むのを防ぎます。
. その後の起動時に CD 上の `autounattend.xml` が再利用されるのを防ぐため、CD-ROM ドライブを取り出します。

== ステップ 4: Pipeline の実行

以下のマニフェストの `REPLACE_WITH_YOUR_ISO_URL` を、ステップ 2 でコピーした URL に置き換えます。

NOTE: PipelineRun の例には特別なパラメーター acceptEula があります。このパラメーターを設定すると、Microsoft 製品の各デプロイメントまたはインストールに適用される Microsoft エンドユーザー使用許諾契約 (EULA) に同意したことになります。これを false に設定した場合、Pipeline は最初のタスクで終了します。

xref:attachment$windows-golden-images/pipelinerun-windows2k25.yaml[pipelinerun-windows2k25.yaml のダウンロード]

[source,yaml]
----
apiVersion: tekton.dev/v1
kind: PipelineRun
metadata:
  generateName: windows2k25-installer-run-
  namespace: default
spec:
  params:
    - name: winImageDownloadURL
      value: "REPLACE_WITH_YOUR_ISO_URL"
    - name: acceptEula
      value: "false"
    - name: preferenceName
      value: windows.2k25.virtio
    - name: autounattendConfigMapName
      value: windows2k25-autounattend
    - name: baseDvName
      value: win2k25
    - name: isoDVName
      value: win2k25
  pipelineRef:
    params:
      - name: catalog
        value: redhat-pipelines
      - name: type
        value: artifact
      - name: kind
        value: pipeline
      - name: name
        value: windows-efi-installer
      - name: version
        value: v4.21.0
    resolver: hub
  taskRunSpecs:
    - pipelineTaskName: modify-windows-iso-file
      podTemplate:
        securityContext:
          fsGroup: 107
          runAsUser: 107
  timeouts:
    pipeline: 1h0m0s
----

PipelineRun を作成します。マニフェストで `generateName` が使用されているため、`oc apply` ではなく `oc create` を使用してください。

[source,bash,role=execute]
----
oc create -f pipelinerun-windows2k25.yaml
----

パイプラインの進行状況を監視します。

[source,bash,role=execute]
----
oc get pipelinerun -n default -w
----

PipelineRun が `Succeeded` と表示されたら、`Ctrl+C` を押して watch を終了します。

パイプラインによって作成された DataVolume を監視することもできます。

[source,bash,role=execute]
----
oc get dv -n default -w
----

=== パイプラインの処理内容

`windows-efi-installer` パイプラインは、以下のステージを実行します。

. **Import autounattend ConfigMap** -- 作成した ConfigMap から `autounattend.xml` および `post-install.ps1` を読み取ります。
. **Download Windows ISO** -- ISO を DataVolume にダウンロードします。
. **Modify ISO** -- インストーラーが「Press any key」の待機なしで起動するように、対話型の EFI ブートローダー (`efisys.bin`) をプロンプトなしのブートローダー (`efisys_noprompt.bin`) に置き換えます。
. **Create blank root disk** -- Windows インストール先として 60 GiB の DataVolume を作成します。
. **Boot installer VM** -- 変更された ISO、空の root ディスク、VirtIO ドライバーコンテナディスクを使用して VM を起動します。`autounattend.xml` により、ユーザーの操作なしでインストール全体が実行されます。
. **Wait for shutdown** -- パイプラインは VM がシャットダウンするのを待ちます。これは `auditUser` パスで sysprep generalize が完了した後に発生します。
. **Create DataSource** -- インストールされた root ディスクを指す DataSource を作成し、クローンソースとして利用できるようにします。
. **Clean up** -- インストーラー VM と一時的な DataVolume (ISO、変更された ISO) を削除します。

パイプライン全体には、ネットワーク速度 (ISO のダウンロード) やストレージパフォーマンス (ディスクのクローン作成) に応じて 30〜60 分かかります。

== ステップ 6: ゴールデンイメージからの VM のデプロイ

ゴールデンイメージからクローンされた各 VM には、初回起動時の OOBE パス中にマシン固有の設定を行うための専用の sysprep `unattend.xml` が必要です。このファイルは ConfigMap に保存され、sysprep ボリュームとして VM にアタッチされます。KubeVirt はこれをフロッピーまたは CD としてマウントし、Windows Setup は OOBE 中にそれを自動的に読み取ります。

----

ConfigMap を適用します。

[source,bash,role=execute]
----
oc apply -f sysprep-unattend-configmap.yaml
----

=== VM の作成

以下の VM は、`win2k25` DataSource からルートディスクをクローンし、sysprep ConfigMap をボリュームとしてアタッチします。`windows.2k25.virtio` preference は Windows 固有のハードウェア構成 (Hyper-V enlightenments、Secure Boot を備えた EFI、TPM、VirtIO デバイスバス、クロック、タイマー設定) を提供し、`u1.large` instancetype は CPU とメモリリソースを定義します。

xref:attachment$windows-golden-images/windows-vm-from-golden.yaml[windows-vm-from-golden.yaml のダウンロード]

[source,yaml]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: win2k25-vm-1
  namespace: default
spec:
  dataVolumeTemplates:
    - apiVersion: cdi.kubevirt.io/v1beta1
      kind: DataVolume
      metadata:
        name: win2k25-vm-1-disk
      spec:
        sourceRef:
          kind: DataSource
          name: win2k25
          namespace: default
        storage:
          resources:
            requests:
              storage: 60Gi
  runStrategy: RerunOnFailure
  instancetype:
    name: u1.large
  preference:
    name: windows.2k25.virtio
  template:
    spec:
      domain:
        devices:
          disks:
            - name: rootdisk
              disk: {}
            - name: sysprep
              cdrom: {}
      volumes:
        - name: rootdisk
          dataVolume:
            name: win2k25-vm-1-disk
        - name: sysprep
          sysprep:
            configMap:
              name: win2k25-sysprep-unattend
----

VM マニフェストを適用します。

[source,bash,role=execute]
----
oc apply -f windows-vm-from-golden.yaml
----

ディスクがクローンされ、VM が起動するまで待ちます。クローンには数分かかり、VM の起動後、Windows OOBE がバックグラウンドで最大 5 分間実行されます。

[source,bash,role=execute]
----
oc get dv win2k25-vm-1-disk -n default -w
----

DataVolume に `Succeeded` と表示されたら、VM のステータスを監視します。

[source,bash,role=execute]
----
oc get vmi win2k25-vm-1 -n default -w
----

VM に `PHASE=Running` および `READY=True` と表示されるまで待機し、`Ctrl+C` を押します。

== ステップ 7: デプロイされた VM の検証

VM インスタンスのステータスを確認します。

[source,bash,role=execute]
----
oc get vmi win2k25-vm-1 -n default
----

[source,text]
.想定される出力
----
NAME            AGE   PHASE     IP             NODENAME     READY
win2k25-vm-1    8m    Running   10.128.1.155   worker-01    True
----

QEMU guest agent によって報告されたゲスト OS 情報をクエリします。

[source,bash,role=execute]
----
oc get vmi win2k25-vm-1 -n default -o jsonpath='{.status.guestOSInfo}' | python3 -m json.tool
----

[source,json]
.想定される出力
----
{
    "id": "mswindows",
    "kernelRelease": "10.0.26100",
    "name": "Microsoft Windows Server 2025 Datacenter",
    "prettyName": "Windows Server 2025 Datacenter",
    "version": "10.0",
    "versionId": "10.0"
}
----

`guestOSInfo` フィールドが空の場合は、さらに数分お待ちください。QEMU guest agent は OOBE の完了後に起動しますが、初回起動時には最大 5 分かかる場合があります。

ホスト名が正しく設定されたことを確認するには、VNC コンソール経由で接続します。
macOS では、`virtctl` は VNC ビューアーを自動検出しないため、`--vnc-type` および `--vnc-path` でビューアーのタイプとパスを指定する必要があります。

[source,bash,role=execute]
----
virtctl vnc win2k25-vm-1 -n default --vnc-type=tiger --vnc-path=/usr/local/bin/vncviewer
----

sysprep ConfigMap のパスワードを使用して `Administrator` としてログインし、**System Properties** またはコマンドプロンプトで `hostname` を実行してホスト名を確認します。

RDP アクセスについては、xref:vm-configuration:remote-access-windows-vms.adoc[Remote Access to Windows VMs via RDP] を参照してください。

== ゴールデンイメージの更新

更新されたゴールデンイメージを作成するには:

. Microsoft Evaluation Center から新しい ISO ダウンロード URL を生成します (または更新されたライセンス付き ISO を使用します)。
. 必要に応じて `autounattend.xml` を変更します (たとえば、インストール後スクリプトに新しいソフトウェアを追加するなど)。
. `win2k25-v2` など、別の `baseDvName` 値を使用してパイプラインを再実行します。
. 新しい DataSource 名を参照するように VM マニフェストを更新します。

必要に応じて以前のバージョンにロールバックできるように、バージョン管理された DataSource 名 (`win2k25-v1`、`win2k25-v2`、`win2k25-2025-07` など) を使用してください。少なくとも 1 つ前のバージョンを利用可能な状態にしておいてください。

== その他の Windows バージョンへの対応

その他の Windows バージョンのゴールデンイメージをビルドするには、PipelineRun パラメーターおよび `autounattend.xml` のドライバーパスを調整します。以下の表に必要な変更点を示します。

[cols="1,1,1,1"]
|===
|バージョン |`preferenceName` |`autounattendConfigMapName` |VirtIO ドライバーパス

|Windows 10
|`windows.10.virtio`
|`windows10-efi-autounattend`
|`viostor/w10/amd64`, `NetKVM/w10/amd64`

|Windows 11
|_ (デフォルト) _
|`windows11-autounattend`
|`viostor/w11/amd64`, `NetKVM/w11/amd64`

|Server 2022
|`windows.2k22.virtio`
|`windows2k22-autounattend`
|`viostor/2k22/amd64`, `NetKVM/2k22/amd64`

|Server 2025
|`windows.2k25.virtio`
|`windows2k25-autounattend`
|`viostor/2k25/amd64`, `NetKVM/2k25/amd64`
|===

また、ターゲット OS のエディション文字列に合わせて `autounattend.xml` の `ImageInstall` セクションを変更する必要があります。たとえば、Windows 11 Enterprise では `Windows Server 2025 SERVERDATACENTER` の代わりに `Windows 11 Enterprise` を使用します。

== トラブルシューティング

[cols="1,2"]
|===
|問題 |解決策

|**パイプラインが `modify-windows-iso-file` で "file not found: efisys_noprompt.bin" エラーにより失敗する**
|ISO にプロンプトなしの EFI ブートローダーが含まれていない可能性があります。このファイルは標準の Microsoft ISO には含まれていますが、カスタム ISO や軽量化された ISO では欠落している場合があります。Microsoft Evaluation Center から入手した変更されていない ISO を使用してください。

|**ISO の変更時に Permission denied が発生する**
|ステップ 4 に示すように、`fsGroup: 107` および `runAsUser: 107` を指定して PipelineRun に `taskRunSpecs` セクションを追加してください。また、`anyuid` SCC が `pipeline` サービスアカウントに付与されていることを確認してください。

|**パイプラインがタイムアウトする**
|PipelineRun マニフェストの `timeouts.pipeline` を増やしてください。ネットワーク接続やストレージバックエンドが遅い場合、パイプラインがデフォルトの 1 時間のタイムアウトを超えることがあります。`oc get dv -w` で DataVolume の進行状況を確認してください。

|**クローンされた VM がデスクトップではなく OOBE ウィザードで起動する**
|sysprep の ConfigMap キーは `autounattend.xml` ではなく `unattend.xml` である必要があります。Windows は、新規インストール時にのみリムーバブルメディアから `autounattend.xml` を読み取ります。sysprep の後は、`unattend.xml` を読み取ります。また、VM の `volumes.sysprep.configMap.name` に指定されている ConfigMap 名が作成した ConfigMap と一致していることを確認してください。

|**Sysprep が "rearm count exceeded" で失敗する**
|評価版 ISO には、sysprep の rearm 回数に制限があります。既存のイメージを再度 sysprep するのではなく、新しい ISO からゴールデンイメージを再構築してください。本番環境で使用する場合は、rearm 制限のないボリュームライセンスの ISO を使用してください。

|**クローンされた VM の起動後の応答が遅い**
|初回起動時、Windows OOBE はバックグラウンドで最大 5 分間実行されます。VM が応答しないと判断する前に、ゲストエージェントが `guestOSInfo` を報告するのを待ってください。

|**ゲストエージェントが OS 情報を報告しない**
|`post-install.ps1` スクリプトによって QEMU guest agent がインストールされたことを確認してください。VM コンソールに接続し、`services.msc` で `QEMU Guest Agent` サービスが実行されていることを確認してください。
|===

== クリーンアップ

このチュートリアルで作成したすべてのリソースを削除します:

[source,bash,role=execute]
----
oc delete vm win2k25-vm-1 -n default
oc delete configmap win2k25-sysprep-unattend -n default
oc delete configmap windows2k25-autounattend -n default
oc delete datasource win2k25 -n default
oc delete dv win2k25 -n default
----

PipelineRun リソースも削除するには:

[source,bash,role=execute]
----
oc delete pipelinerun -l tekton.dev/pipeline=windows-efi-installer -n default
----

ステップ 1 で付与した SCC を取り消すには:

[source,bash,role=execute]
----
oc adm policy remove-scc-from-user anyuid -z pipeline -n default
----

== まとめ

このチュートリアルでは、以下を行いました:

* VirtIO ドライバーの挿入と sysprep による一般化を伴う Windows Server 2025 の無人インストール用に `autounattend.xml` ConfigMap を設定
* Windows ISO からゴールデンイメージをビルドするために `windows-efi-installer` Tekton パイプラインを実行
* 生成された DataVolume および DataSource を確認
* クローンごとの sysprep カスタマイズ (ホスト名、管理者パスワード、RDP) を使用して、ゴールデンイメージから VM をデプロイ
* ゲストエージェント情報を使用してデプロイされた VM を確認
* ゴールデンイメージを更新し、他の Windows バージョン向けにプロセスを適応させる方法を学習しました
