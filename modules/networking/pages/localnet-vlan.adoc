= OpenShift Virtualization における NetworkAttachmentDefinition を使用した VLAN 対応の localnet セカンダリーネットワークの構成
:navtitle: NAD を使用した VLAN 対応の localnet セカンダリーネットワーク

本チュートリアルでは、OpenShift Virtualization において、NetworkAttachmentDefinition (NAD) を使用して VLAN タグ付けを行う localnet セカンダリーネットワークを構成する方法を解説します。このアプローチでは、VLAN セグメンテーションを伴う物理ネットワークインフラへの直接アクセスが提供され、Pod ネットワークの接続性を維持したまま、仮想マシン (VM) が特定の VLAN タグ付きネットワークと通信できるようになります。これは、既存の VLAN ベースのネットワークと統合する場合や、ネットワークセグメンテーションが必要な場合に最適です。

== 前提条件

* **NMState Operator**: クラスター内にインストールされ、実行中であること
* **NMState CR**: Operator が実行された後に nmstate インスタンスが作成されていること
* **Worker Node**: bridge mapping が Worker Node に適用されること
* **VLAN インフラストラクチャ**: 物理ネットワークインフラが VLAN タグ付けをサポートしていること
* **スイッチ設定**: OpenShift Worker Node に接続されている物理スイッチポートが、複数の VLAN タグ付きトラフィックストリームを処理するために**トランクモード**で構成されていること

検証済みバージョン:
----
OpenShift 4.19
----

== ネットワーク構成要件

=== 物理スイッチの設定: トランクモード

OpenShift Worker Node に接続されている物理スイッチポートは、localnet VLAN 構成を正しく機能させるために**トランクモードで構成されている必要があります**:

* **トランクモード**: スイッチポートが複数の VLAN のトラフィックを運ぶことを許可します
* **VLAN タグ付け**: 各 VLAN は一意の VLAN ID (例: 100, 200, 300) によって識別されます
* **複数のネットワーク**: 複数の VLAN ベースのセカンダリーネットワークをサポートするために不可欠です

== 手順 1: VM の namespace の作成

VLAN 構成対応の localnet セカンダリーネットワークを使用する VM 用の namespace を作成します。

xref:attachment$localnet-vlan/localnet-vlan-namespace.yaml[localnet-vlan-namespace.yaml をダウンロード]

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: v1
kind: Namespace
metadata:
  name: vm-guests-vlan
EOF
----

== 手順 2: bridge mapping の構成

論理ネットワークインターフェース名 `localnet-vlan` を Worker Node 上の `br-ex` ブリッジインターフェースに接続する bridge mapping を構成します。このマッピングにより、OVN-Kubernetes に対してどの物理ブリッジインターフェースが VLAN サポート付きの localnet トラフィックを処理するかを通知し、基盤となる物理ネットワークインフラ経由で VM が VLAN タグ付き外部ネットワークにアクセスできるようにします。

xref:attachment$localnet-vlan/localnet-vlan-bridge-mapping-nncp.yaml[localnet-vlan-bridge-mapping-nncp.yaml をダウンロード]

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: nmstate.io/v1
kind: NodeNetworkConfigurationPolicy
metadata:
  name: localnet-vlan-bridge-mapping
spec:
  nodeSelector:
    node-role.kubernetes.io/worker: ''  
  desiredState:
    ovn:
      bridge-mappings:
      - localnet: localnet-vlan
        bridge: br-ex
        state: present
EOF
----

== 手順 3: VLAN 対応の NetworkAttachmentDefinition の作成

セカンダリーネットワーク接続用に、VLAN タグ付けを伴う localnet トポロジーを構成する NetworkAttachmentDefinition を作成します。

xref:attachment$localnet-vlan/localnet-vlan-100-nad.yaml[localnet-vlan-100-nad.yaml をダウンロード]

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: "k8s.cni.cncf.io/v1"
kind: NetworkAttachmentDefinition
metadata:
  name: localnet-vlan-100
  namespace: vm-guests-vlan
spec:
  config: '{
    "cniVersion": "0.3.1",
    "name": "localnet-vlan-100",
    "type": "ovn-k8s-cni-overlay",
    "topology": "localnet",
    "netAttachDefName": "vm-guests-vlan/localnet-vlan-100",
    "physicalNetworkName": "localnet-vlan",
    "vlanID": 100,
    "subnets": "192.168.100.0/24",
    "excludeSubnets": "192.168.100.1/32"
  }'
EOF
----

**構成の詳細**:

* `physicalNetworkName: "localnet-vlan"`: この NetworkAttachmentDefinition (NAD) を NNCP で構成された bridge mapping にリンクします (bridge-mappings 内の `localnet` 名と一致させる必要があります)
* `vlanID: 100`: ネットワークセグメンテーション用に VLAN タグ 100 を指定します
* `subnets`: OVN-Kubernetes IPAM 用の IP サブネット範囲を定義します
* `excludeSubnets`: ゲートウェイ IP が割り当てられないように除外します (通常はルーター/ゲートウェイ用に予約されます)
* `topology: "localnet"`: 物理ネットワークへの直接アクセスのために localnet トポロジーを使用します

== 手順 4: VLAN ネットワーク接続を備えた VM のデプロイ

Pod ネットワークと VLAN タグ付き localnet セカンダリーネットワークの両方に接続する VM を作成します。

WARNING: この例の cloud-init パスワードはデモ目的のみのものです。本番環境では、常に強力で一意なパスワード、または SSH 鍵認証を使用してください。

xref:attachment$localnet-vlan/fedora-vlan-vm.yaml[fedora-vlan-vm.yaml をダウンロード]

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: fedora-vlan-vm
  namespace: vm-guests-vlan
  labels:
    app: fedora-vlan-vm
spec:
  runStrategy: Always
  dataVolumeTemplates:
  - metadata:
      name: fedora-vlan-volume
    spec:
      pvc:
        accessModes:
        - ReadWriteOnce
        resources:
          requests:
            storage: 33Gi
      sourceRef:
        kind: DataSource
        name: fedora
        namespace: openshift-virtualization-os-images
  template:
    metadata:
      labels:
        app: fedora-vlan-vm
    spec:
      domain:
        devices:
          disks:
          - name: datavolumedisk
            disk:
              bus: virtio
          - name: cloudinitdisk
            disk:
              bus: virtio
          interfaces:
          - name: default
            bridge: {}
          - name: vlan_network
            bridge: {}
        resources:
          requests:
            memory: 2Gi
            cpu: 1
      networks:
      - name: default
        pod: {}
      - name: vlan_network
        multus:
          networkName: localnet-vlan-100
      volumes:
      - name: datavolumedisk
        dataVolume:
          name: fedora-vlan-volume
      - name: cloudinitdisk
        cloudInitNoCloud:
          userData: |
            #cloud-config
            user: fedora
            password: fedora
            chpasswd: { expire: False }
            packages:
            - python3
            - tcpdump
            - net-tools
            runcmd:
            - echo "<h1>Welcome to OpenShift Virtualization VLAN Network!</h1>" > /root/index.html
            - echo "<p>VLAN ID: 100</p>" >> /root/index.html
            - echo "<p>Network: 192.168.100.0/24</p>" >> /root/index.html
            - cd /root && nohup python3 -m http.server 8080 > /dev/null 2>&1 &
EOF
----

== 手順 5: VLAN ネットワーク接続の確認

VM コンソールにアクセスし、VLAN 構成によるデュアルネットワーク接続を確認します。

[source,bash,role=execute]
----
# VM のステータスを確認
oc get vm -n vm-guests-vlan

# 実行中の VM インスタンスを確認
oc get vmi -n vm-guests-vlan

# VM コンソールにアクセス (認証情報: cloud-init 経由で fedora/fedora)
virtctl console -n vm-guests-vlan fedora-vlan-vm
----

VM コンソール内で、VLAN ネットワーク構成を確認します:

[source,bash,role=execute]
----
# ネットワークインターフェースを確認 - プライマリ (Pod ネットワーク) とセカンダリー (VLAN ネットワーク)
ip addr show

# ルートを確認 - 2 つのデフォルトゲートウェイ (低い metric が優先)
# プライマリネットワーク: metric 100、セカンダリー VLAN: metric 101
ip route show

# 想定される出力例:
default via 10.128.0.1 dev enp1s0 proto dhcp src 10.128.0.172 metric 100 
default via 192.168.100.1 dev enp2s0 proto dhcp src 192.168.100.50 metric 101 

# 外部接続をテスト
ping 8.8.8.8

# Web サービスが実行中であることを確認
curl localhost:8080

# VLAN インターフェースの接続をテスト (<vlan-ip> を実際の IP に置き換え)
curl <vlan-ip>:8080

# VLAN タグ付けを確認 (tcpdump が利用可能な場合)
# セカンダリーインターフェース上の VLAN タグ付きトラフィックを表示
sudo tcpdump -i enp2s0 -nn vlan 100
----

== トラブルシューティング

=== 一般的な問題

. **VM まで VLAN トラフィックが到達しない**:
   * 物理スイッチ構成が VLAN タグ付けをサポートしているか確認する
   * Worker Node の bridge mapping 構成を確認する
   * VLAN ID がネットワークインフラと一致していることを確認する

. **IP アドレスの割り当て問題**:
   * VLAN ネットワーク上で DHCP サーバーが利用可能であることを確認する

. **ネットワーク接続の問題**:
   * 物理ネットワークが構成された VLAN をサポートしていることを確認する
   * 物理ネットワークから VLAN サブネットへの接続をテストする

=== 確認コマンド

[source,bash,role=execute]
----
# NetworkAttachmentDefinition のステータスを確認
oc get network-attachment-definitions -n vm-guests-vlan

# Worker Node 上の bridge mapping を確認
oc get nncp localnet-vlan-bridge-mapping -o yaml

# VM のネットワークステータスを確認
oc get vmi -n vm-guests-vlan -o yaml | grep -A 10 networks

# トラブルシューティング用に OVN-Kubernetes のログを表示
oc logs -n openshift-ovn-kubernetes -l app=ovnkube-node
----

== まとめ

本チュートリアルでは、以下の内容を学習しました:

* Worker Node 上で `NodeNetworkConfigurationPolicy` を使用して、VLAN サポートを備えた bridge mapping を構成する方法
* localnet トポロジー、VLAN タグ付け、および OVN-Kubernetes IPAM を備えた `NetworkAttachmentDefinition` を作成する方法
* VLAN タグ付きトラフィックをサポートするために物理スイッチポートをトランクモードで構成する必要がある理由
* Pod ネットワークと VLAN タグ付き localnet を組み合わせたデュアルネットワーク接続を備えた VM をデプロイする方法
* VLAN ネットワーク構成を検証し、一般的な VLAN 接続の問題をトラブルシューティングする方法
