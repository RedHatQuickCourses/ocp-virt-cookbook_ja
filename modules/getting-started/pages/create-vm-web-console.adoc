= Web コンソールを使用したテンプレートからの VM の作成
:navtitle: Web コンソールを使用した VM の作成

== 概要

このチュートリアルでは、OpenShift Web コンソールと事前構築済みテンプレートを使用して仮想マシン (VM) を作成する方法を説明します。Web コンソールは、VM 管理のための直感的なグラフィカルインターフェースを提供するため、新規ユーザーの出発点です。

== テンプレートベースの VM 作成の仕組み

Web コンソールでテンプレートから VM を作成すると、OpenShift Virtualization はバックグラウンドで一連のリソース操作をトリガーします。このフローを理解することで、プロビジョニングの問題のトラブルシューティングやストレージ要件の計画に役立ちます。

[source,text]
----
                                 openshift-virtualization-os-images namespace
                                +------------------------------------------+
                                |                                          |
  VM Template                   |   DataSource                             |
  (VM spec、ブートソース      ---------->  (特定のOSバージョンの                |
   の参照、CPU/memory        |   |    ゴールデンイメージPVCを指す)              |
   デフォルト値の定義)         |   |        |                                 |
                            |   +------------------------------------------+
                            |            |
                            |            |  クローン操作
                            |            v
                            |   +------------------------------------------+
                            |   |  your-project namespace                  |
                            |   |                                          |
                            |   |   DataVolume                             |
                            |   |   (クローンを管理し、                       |
                            |   |    OS ディスクを含む PVC を作成)            |
                            |   |        |                                 |
                            |   |        v                                 |
                            |   |   PVC                                    |
                            |   |   (クローン作成された OS イメージを含む       |
                            |   |    永続ディスク)                           |
                            |   |        |                                 |
                            |   |        v                                 |
                            |   |   virt-launcher pod                      |
                            |   |   (QEMU/KVM を実行し、                    |
                            |   |    PVC をマウントして VM を起動)            |
                            |   |        |                                 |
                            |   |        v                                 |
                            |   |   実行中の VirtualMachineInstance         |
                            |   |                                          |
                            |   +------------------------------------------+
----

このフローにおける主要なステップは以下のとおりです。

. **Template** は、ブートディスク用の DataSource への参照と、デフォルトの CPU、メモリ、デバイス設定を含む VirtualMachine spec を定義します。
. `openshift-virtualization-os-images` namespace 内の **DataSource** は、選択されたオペレーティングシステム用に事前インポートされたゴールデンイメージ PVC を指します。
. お使いのプロジェクトの namespace に **DataVolume** が作成されます。これにより、ゴールデンイメージ PVC のクローン作成がオーケストレーションされます。
. クローン操作により、OS ディスクのコピーを含む **PVC** がプロジェクトの namespace に生成されます。
. **virt-launcher pod** が起動し、PVC をマウントして QEMU/KVM 経由で VM を実行します。
. **VirtualMachineInstance** (VMI) は実行中の VM を表し、そのステータス、IP アドレス、ノード配置をレポートします。

NOTE: クローン操作の所要時間は、ディスクサイズとストレージバックエンドによって異なります。スマートクローン (CSI ボリュームクローンまたはスナップショットベースのクローン) をサポートするストレージクラスは、ホスト支援型コピーよりも高速に完了します。

== 前提条件

* OpenShift Virtualization Operator がインストールされた OpenShift 4.18 以降 (link:https://docs.redhat.com/en/documentation/openshift_container_platform/latest/html/virtualization/installing[OpenShift Virtualization のインストール,window=_blank]を参照)
* VM を作成する権限を持つ OpenShift Web コンソールへのアクセス
* VM ディスクプロビジョニング用に構成されたデフォルト StorageClass
* クラスター内で利用可能なブートソースイメージ (DataSource)

ブートソースが利用可能であることを確認します。

[source,bash,role=execute]
----
oc get datasources -n openshift-virtualization-os-images
----

== ステップ 1: 仮想化セクションへのアクセス

. OpenShift Web コンソールにログインします。
. 左側のナビゲーションメニューで、**Virtualization** をクリックします。
. **VirtualMachines** をクリックして、VM 管理インターフェースを表示します。

image::virtualization-menu.png[VirtualMachines が選択された状態の仮想化メニュー]

VirtualMachines ページには、選択したプロジェクト内のすべての VM と、そのステータスおよび基本情報が表示されます。

== ステップ 2: 利用可能なテンプレートの参照

OpenShift Virtualization には、一般的なオペレーティングシステム用の事前構成済みテンプレートが含まれています。

. VirtualMachines ページから、**Create** -> **From template** をクリックします。
. オペレーティングシステムごとに整理された利用可能なテンプレートを参照します。
** **Red Hat Enterprise Linux** - 様々な RHEL バージョン
** **Fedora** - 最新の Fedora リリース
** **CentOS Stream** - CentOS Stream バージョン
** **Microsoft Windows** - Windows Server およびデスクトップバージョン

image::vm-templates-catalog.png[OS オプションが表示されたテンプレートカタログ]

TIP: **Source available** と表示されているテンプレートには、すぐに使用できる事前構成済みのブートソースがあります。これには、クラスター内で xref:default-storage-class.adoc[デフォルト StorageClass] が構成されている必要があります。

各テンプレートには以下が含まれています。

* 事前構成済みの CPU およびメモリ設定
* OS に適したディスクサイズ
* ブートソース参照 (DataSource)
* cloud-init または sysprep 構成 (該当する場合)

== VM テンプレートに含まれるもの

VM テンプレートは、VirtualMachine マニフェストをパラメーター化されたフィールドでラップした OpenShift Template リソースです。Web コンソールでテンプレートを選択すると、コンソールによってそれらのパラメーター (VM 名、namespace、ディスクサイズ) が入力され、完全な VirtualMachine オブジェクトが生成されます。

テンプレートは、次の 3 つの点で生の VirtualMachine マニフェストと異なります。

* **パラメーター** -- `${NAME}` や `${DATA_SOURCE_NAME}` などのフィールドは、作成時に置き換えられます。これにより、1 つのテンプレートから異なる名前や設定を持つ多数の VM を生成できます。
* **DataSource 参照** -- テンプレートはディスクイメージの URL や PVC を直接指定する代わりに、`openshift-virtualization-os-images` namespace 内の DataSource を参照します。DataSource はブートイメージの場所を抽象化するため、基盤となるゴールデンイメージが更新された場合でもテンプレートの有効性が維持されます。
* **Web コンソールのアノテーション** -- テンプレートには `template.kubevirt.io/type`、`name.os.template.kubevirt.io`、`description` などのアノテーションが含まれており、カタログでテンプレートをどのように表示するか、どのアイコンを表示するか、どのようなデフォルト値を提示するかを Web コンソールに伝えます。

テンプレートの構造は、任意のテンプレートを検査して確認できます。

[source,bash,role=execute]
----
oc get template fedora-server-small -n openshift -o yaml
----

出力の下部には `parameters` セクションが表示され、`objects` セクションには VirtualMachine オブジェクトの定義が表示されます。Web コンソールは両方のセクションを読み取り、VM 作成時に表示されるカスタマイズフォームを構築します。

TIP: 組織に合わせてカスタマイズしたテンプレートを作成するには、xref:vm-configuration:vm-templates.adoc[カスタム VM テンプレートの作成] を参照してください。

== ステップ 3: テンプレートからの VM 作成

この例では、Fedora VM を作成します。他のオペレーティングシステムの場合も手順は同様です。

=== テンプレートの選択

. **Fedora** テンプレートタイルをクリックします。
. サイドパネルに表示されるテンプレートの詳細を確認します。
. **Customize VirtualMachine** をクリックします。

image::fedora-template-details.png[Fedora テンプレート詳細パネル]

=== VM 詳細の構成

**Customize VirtualMachine** ページで、**Overview** タブの VM 設定を構成します。

. **Name**: VM の名前を入力します (例: `fedora-test-vm`)。
. **Project**: VM を作成するプロジェクト (namespace) を選択します。
. **Boot source**: デフォルトで Fedora の DataSource が表示されているはずです。
. **CPU**: CPU コア数を調整します (通常、デフォルトは 1)。
. **Memory**: RAM 割り当てを調整します (デフォルト値はテンプレートによって異なります)。

image::vm-customize-overview.png[VM カスタマイズの Overview タブ]

=== ストレージのカスタマイズ (オプション)

**Disks** タブをクリックしてストレージを変更します。

. ルートディスクの構成を確認します。
. 必要に応じてディスクサイズを調整したり、追加のディスクを追加したりします。
. StorageClass がニーズに適していることを確認します。

image::vm-customize-disks.png[VM カスタマイズの Disks タブ]

=== 確認と作成

. タブ全体の設定を確認します。
. **Create VirtualMachine** をクリックします。
. 必要に応じて、**Start this VirtualMachine after creation** にチェックを入れて、作成後にすぐに起動します。

image::vm-create-button.png[Create VirtualMachine ボタン]

== ステップ 4: VM 作成の監視

作成をクリックすると、VM 詳細ページにリダイレクトされます。

=== プロビジョニングの進捗確認

VM は作成中にいくつかのフェーズを通過します。

. **Provisioning** - ブートソースからディスクがクローンされています。
. **Starting** - VM が起動しています (起動が選択されている場合)。
. **Running** - VM が完全に動作しています。

image::vm-provisioning-status.png[VM プロビジョニングのステータス]

**Events** タブを監視して、詳細なプロビジョニング手順を確認します。

[source,bash,role=execute]
----
# CLI からイベントを監視することが可能
oc get events -n <your-namespace> --field-selector involvedObject.name=<vm-name> -w
----

=== VM が実行中であることの確認

プロビジョニングが完了すると、ステータスが **Running** に変わります。

image::vm-running-status.png[VM 実行中のステータス]

== ステップ 5: VM コンソールへのアクセス

Web コンソールは、VM のグラフィカルコンソールへの直接アクセスを提供します。

=== コンソールの起動

. VM 詳細ページで、**Console** タブをクリックします。
. ブラウザ内で直接 VNC コンソールが読み込まれます。

image::vm-console-tab.png[上部に資格情報が表示された VM コンソール]

=== コンソールのオプション

コンソールツールバーでは、以下のオプションが提供されます。

* **Send key** - 特殊なキーの組み合わせを送信 (Ctrl+Alt+Del など)
* **Disconnect** - コンソール接続を閉じる
* **Guest credentials** - テンプレートが提供するユーザー名とパスワード


TIP: パフォーマンスを向上させるには、日常的な作業では Web コンソールではなく、xref:vm-configuration:remote-access-linux-vms.adoc[Linux VM への SSH アクセス] または xref:vm-configuration:remote-access-windows-vms.adoc[Windows VM への RDP] を使用することを検討してください。

=== ゲストへのログイン

Fedora やその他のクラウドイメージの場合、デフォルトの資格情報は cloud-init 構成に依存します。

* cloud-init ユーザーデータが提供されていない場合は、ユーザーのセットアップが必要になることがあります。
* デフォルトの資格情報については、テンプレートのドキュメントを確認してください。
* 自動化されたユーザーセットアップを行うために、テンプレート内の cloud-init をカスタマイズすることを検討してください。

== ステップ 6: 基本的な VM 操作

Web コンソールは、一般的な VM 操作への容易なアクセスを提供します。

=== VM アクションメニュー

VM 詳細ページまたは VirtualMachines リストから、アクションメニューにアクセスします。

image::vm-actions-menu.png[VM アクションのドロップダウンメニュー]

=== VM の停止

. **Actions** -> **Stop** をクリックします。
. メッセージが表示されたら、アクションを確定します。
. VM が正常にシャットダウンされます。

[source,bash,role=execute]
----
# CLI での操作
virtctl stop <vm-name>
----

=== VM の再起動

. **Actions** -> **Restart** をクリックします。
. VM が正常に再起動します。

[source,bash,role=execute]
----
# CLI での操作
virtctl restart <vm-name>
----

=== 一時停止と一時停止の解除

VM を一時停止すると、シャットダウンせずにその状態が凍結されます。

. **Actions** -> **Pause** をクリックします。
. VM の状態がメモリ内に保持されます。
. **Actions** -> **Unpause** をクリックして再開します。

NOTE: 一時停止中の VM は、ノード上のメモリリソースを引き続き消費します。

=== VM の削除

. **Actions** -> **Delete** をクリックします。
. 関連付けられたディスク (PVC) を削除するかどうかを選択します。
. 削除を確定します。

image::vm-delete-confirmation.png[VM 削除の確認ダイアログ]

TIP: 削除後も VM ディスク (DataVolume) を保持するには、確認ダイアログに表示される **Delete disk** オプションのチェックを外します。これにより、後で新しい VM でそのディスクを再利用できます。

WARNING: ディスクを含めて VM を削除すると、元に戻すことはできません。必要に応じてバックアップがあることを確認してください。

== ステップ 7: VM の詳細とメトリクスの表示

VM 詳細ページでは、監視および構成に関する情報を提供します。

=== Overview タブ

一目で主要な情報を確認できます。

* VM のステータスと状態
* IP アドレス (ゲストエージェントがインストールされている場合)
* CPU およびメモリの使用率
* ブート順序とデバイス

image::vm-overview-tab.png[詳細が表示された VM の Overview タブ]

=== Metrics タブ

リアルタイムのパフォーマンスメトリクスを表示します。

* 時間経過に伴う CPU 使用率
* メモリ使用率
* ネットワークスループット
* ストレージ I/O

image::vm-metrics-tab.png[グラフが表示された VM の Metrics タブ]

NOTE: 完全なメトリクスを表示するには、VM 内に QEMU guest agent がインストールされている必要があります。

=== YAML タブ

VM 定義を直接表示および編集します。

. **YAML** タブをクリックします。
. VirtualMachine マニフェストを確認または変更します。
. **Save** をクリックして変更を適用します。

image::vm-yaml-tab.png[マニフェストエディタが表示された VM の YAML タブ]

TIP: **Download** ボタンをクリックして、YAML ファイルをダウンロードすることもできます。

== クイック作成を使用した VM の作成

デフォルト設定を使用してより迅速に VM を作成するには、クイック作成オプションを使用します。

. VirtualMachines ページから、**Create** -> **From template** をクリックします。
. テンプレートを選択します。
. **Customize VirtualMachine** ではなく、**Quick create VirtualMachine** をクリックします。
. VM がデフォルト設定ですぐに作成されます。

image::vm-quick-create.png[Quick create VirtualMachine オプション]

この設定は、以下の場合に有用です。

* テスト環境や開発環境
* デフォルトのテンプレート設定で問題ない場合
* ラピッドプロトタイピング

== 適切な VM 作成方法の選択

OpenShift Virtualization には、VM を作成するための複数の方法が用意されています。それぞれの方法は異なるニーズに適しています。適切なアプローチを選択するには、以下のガイダンスを参考にしてください。

=== テンプレートからのクイック作成

最適な用途: テスト、デモ、および使い捨ての開発用 VM。

テンプレートのデフォルト設定を受け入れるだけで、数秒で VM を稼働させることができます。設定する項目はありません。VM を迅速に用意する必要があり、特定のリソース設定を重視しない場合に使用します。

=== カスタマイズされたテンプレート

最適な用途: 特定の CPU、メモリ、ディスクサイズを必要とするものの、標準テンプレートの OS デフォルト設定を使用できる VM。

テンプレートを選択した後、作成前に Web コンソールで個々のフィールド (コア数、メモリ、ディスクサイズ、cloud-init ユーザーデータ) を調整します。これは日常的な作業で最も一般的な方法です。

=== カスタム YAML マニフェスト

最適な用途: 自動化、GitOps パイプライン、マルチ NIC 構成、およびすべてのフィールドを完全に制御する必要があるケース。

VirtualMachine マニフェストを直接記述し、`oc apply -f` を使用して適用します。このアプローチは、バージョン管理や CI/CD システムと統合されます。詳細は xref:create-vm-cli-yaml.adoc[CLI と YAML マニフェストを使用した VM の作成] を参照してください。

=== カスタムテンプレート

最適な用途: 標準化された VM 構成を持ち、事前に承認された VM タイプをチームに提供したい組織。

組織の標準 (承認済み OS イメージ、ネットワークポリシー、リソース制限、必須ラベル) をエンコードした OpenShift Template を作成します。チームは、基盤となる構成を意識することなく、Web コンソールを介してこれらのテンプレートから VM を作成できます。手順については xref:vm-configuration:vm-templates.adoc[カスタム VM テンプレートの作成] を参照してください。

* Web ブラウザを通じた VM コンソールへのアクセス
