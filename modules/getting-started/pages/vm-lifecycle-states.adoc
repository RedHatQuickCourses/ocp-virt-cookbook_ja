= VM ライフサイクルの状態と基本操作の理解
:navtitle: VM ライフサイクルの状態

== 概要

OpenShift Virtualization における仮想マシンのライフサイクルを理解することは、効果的な VM 管理、トラブルシューティング、自動化に不可欠です。本ガイドでは、VirtualMachine リソースと VirtualMachineInstance リソースの関係、VM のさまざまな状態、ライフサイクル全体を通じて VM を管理する方法について説明します。

テスト済みバージョン:
----
OpenShift 4.20
----

== 前提条件

* OpenShift Virtualization がインストールされた OpenShift 4.18 以上
* OpenShift Web コンソールまたは CLI ツール (`oc`、`virtctl`) へのアクセス権
* クラスター内で作成済みの VM が少なくとも 1 つ存在すること (xref:create-vm-web-console.adoc[] を参照)

== VirtualMachine と VirtualMachineInstance の違い

OpenShift Virtualization では、仮想マシンを管理するために主に 2 つのリソースを使用します。

=== VirtualMachine (VM)

`VirtualMachine` リソースは、VM の永続的な定義です。これは、以下を定義するテンプレートまたは仕様書と考えてください。

* VM の名前と namespace
* CPU とメモリの構成
* ディスクとネットワークのアタッチメント
* ブート順序とファームウェア設定
* 実行戦略 (VM の動作方法)

VirtualMachine リソースは、VM が実行中であるかどうかにかかわらず存在します。

[source,bash,role=execute]
----
# 仮想マシンリソースを一覧表示
oc get vm -n my-vms
----

出力例:
[source,text]
----
NAME            AGE   STATUS    READY
fedora-app-vm   14m   Running   True
----

=== VirtualMachineInstance (VMI)

`VirtualMachineInstance` リソースは、実際に実行中の VM インスタンスを表します。これは VM が起動したときに作成され、VM が停止したときに削除されます。VMI には以下が含まれます。

* ランタイム情報 (IP アドレス、ノード配置)
* 現在のフェーズ/状態
* guest agent 情報 (インストールされている場合)

[source,bash,role=execute]
----
# VirtualMachineInstance リソースを一覧表示
oc get vmi -n my-vms
----

出力例:
[source,text]
----
NAME            AGE   PHASE     IP             NODENAME   READY
fedora-app-vm   78s   Running   10.128.0.184   ocplab01   True
----

NOTE: 停止中の VM には VirtualMachine リソースは存在しますが、VirtualMachineInstance は存在しません。VM を起動すると VMI が作成されます。VM を停止すると VMI は削除されますが、VM リソースは残ります。

== VM ライフサイクルの状態

VM は、そのライフサイクルを通じていくつかの状態に遷移します。これらの状態を理解することで、監視やトラブルシューティングが容易になります。

=== 状態の説明

[cols="1,1,3,2",options="header"]
|===
|順序 |状態 |説明 |VMI の存在

|1
|Stopped (停止)
|VM は定義されていますが、実行されていません。計算リソースは消費されません。
|いいえ

|2
|Pending (保留中)
|VMI が作成され、前提条件 (ストレージ、ネットワーク) が揃うのを待っています。
|はい

|3
|Scheduling (スケジュール中)
|Kubernetes スケジューラーが適切なノードを探しています。
|はい

|4
|Starting (起動中)
|割り当てられたノード上で VM が起動しています。
|はい

|5
|Running (実行中)
|VM は完全に動作しており、接続が可能です。
|はい

|6
|Paused (一時停止)
|VM の実行がフリーズしています。状態はメモリ内に保持されます。
|はい

|7
|Stopping (停止中)
|正常終了の処理中です。
|はい

|8
|Terminating (終了中)
|VMI リソースの最終的なクリーンアップ中です。
|はい (短時間)
|===

=== 状態遷移図

次の図は、VM が状態間をどのように遷移するかを示しています。各矢印は操作または自動遷移を表します。

[source,text]
----
  ┌──────┐      start   ┌──────┐           ┌────────┐            ┌───────┐
  │ Stopped │─────────►│ Pending │───────►│ Scheduling │───────►│ Starting │
  └──────┘              └──────┘           └────────┘            └───┬───┘
       ▲                                                                                │
       │                                                                                ▼
  ┌──┴─────┐         ┌───────┐   stop   ┌──────┐    pause     ┌─────┐
  │ Terminating │◄──────│ Stopping │◄──────│ Running │────────►│ Paused  │
  └────────┘         └───────┘          └───┬──┘◄────────└─────┘
                                                           │         unpause
                                                        migrate
                                                           │
                                                           ▼
                                                  ┌───────┐
                                                  │ Migrating │──► Running (new node)
                                                  └───────┘
----

* **Start** は、停止した VM を Pending、Scheduling、Starting を経由して Running に遷移させます。
* **Stop** は、実行中の VM を Stopping および Terminating を経由して Stopped に戻します。
* **Restart** は、すべての中間状態を経由して、完全な停止と起動のサイクルを実行します。
* **Pause/Unpause** は、VMI のライフサイクルを変更することなく、実行を一時停止および再開します。
* **Migrate** は、VM を Running 状態のまま別のノードにライブマイグレーションします。
* **Delete** は、任意の状態から VM リソースを完全に削除します。

=== ライブマイグレーションとライフサイクル

ライブマイグレーションは、ダウンタイムなしで実行中の VM をあるノードから別のノードに移動します。マイグレーションは以下のような場面で発生します。

* **Node drain** -- メンテナンスのためにノードが cordon された場合、実行中の VM は自動的に他のノードにマイグレーションされます。
* **クラスターのアップグレード** -- OpenShift は Worker Node を 1 台ずつローリング更新し、各ノード上の VM のマイグレーションをトリガーします。
* **リバランス** -- 管理者または descheduler が VM をマイグレーションして、ノード間でワークロードをより均等に分散する場合があります。

マイグレーション中、VM は一時的に VMI ステータスに表示される `Migrating` フェーズに入ります。このプロセスの間、VM にはアクセス可能なままです。マイグレーションには共有ストレージ (ReadWriteMany PVC) が必要であるか、または非共有ストレージ設定のための post-copy マイグレーションが使用されます。

== VM ライフサイクルの管理

=== VM の起動

停止中の VM を起動するには：

**Web コンソール:**

. **Virtualization** -> **VirtualMachines** に移動します。
. リストから対象の VM を見つけます。
. VM 名をクリックして詳細を開き、**Actions** -> **Start** をクリックします。
. または、ケバブメニュー (縦に並ぶ 3 つの点) をクリックして **Start** を選択します。
+
image::vm-lifecycle-states/vm-stopped-start-action.png[VM 詳細ページ。Actions メニューの Start オプションを表示]

**CLI:**

[source,bash,role=execute]
----
virtctl start fedora-app-vm -n my-vms
----

**VM が起動したことを確認:**

[source,bash,role=execute]
----
# VM の状態を確認
oc get vm fedora-app-vm -n my-vms

# VMI が作成されたことを確認
oc get vmi fedora-app-vm -n my-vms
----

出力例:
[source,text]
----
NAME            AGE   STATUS    READY
fedora-app-vm   14m   Running   True

NAME            AGE   PHASE     IP             NODENAME   READY
fedora-app-vm   78s   Running   10.128.0.184   ocplab01   True
----

=== VM の停止

VM を停止すると、正常終了の処理が行われ、VMI が削除されます。

**Web コンソール:**

. VM の詳細ページに移動します。
. **Actions** -> **Stop** をクリックします。
+
image::vm-lifecycle-states/vm-running-stop-action.png[VM 詳細ページ。Actions メニューの Stop オプションを表示]

**CLI (正常停止):**

[source,bash,role=execute]
----
virtctl stop fedora-app-vm -n my-vms
----

**CLI (強制停止):**

VM が応答しない場合は、強制停止を使用します。

[source,bash,role=execute]
----
virtctl stop fedora-app-vm -n my-vms --force
----

WARNING: 強制停止は電源コードを抜くのと同じです。正常終了が失敗した場合のみ使用してください。

**VM が停止したことを確認:**

[source,bash,role=execute]
----
# VM は停止状態になっているはずです。
oc get vm fedora-app-vm -n my-vms

# VMI は存在しないはずです。
oc get vmi fedora-app-vm -n my-vms
----

出力例:
[source,text]
----
NAME            AGE   STATUS    READY
fedora-app-vm   14m   Stopped   False

Error from server (NotFound): virtualmachineinstances.kubevirt.io "fedora-app-vm" not found
----

=== VM の一時停止と再開

一時停止 (Pause) は、VM の状態をメモリ内に保持したまま実行を凍結します。これは以下の場合に役立ちます。

* CPU リソースを一時的に解放
* 一貫性のあるスナップショットを取得
* デバッグや調査

IMPORTANT: 一時停止中の VM もノード上のメモリを消費します。CPU 実行のみが中断されます。

**Web コンソール:**

. VM の詳細ページに移動します。
. **Actions** -> **Pause** をクリックします。
. 再開するには: **Actions** -> **Unpause** をクリックします。
+
image::vm-lifecycle-states/vm-running-pause-action.png[VM 詳細ページ。Actions メニューの Pause オプションを表示]
+
image::vm-lifecycle-states/vm-paused-unpause-action.png[VM 詳細ページ。Actions メニューの Unpause オプションを表示]

**CLI:**

[source,bash,role=execute]
----
# VM を一時停止
virtctl pause vm fedora-app-vm -n my-vms

# VM の一時停止を解除
virtctl unpause vm fedora-app-vm -n my-vms
----

**一時停止状態を確認:**

[source,bash,role=execute]
----
oc get vm fedora-app-vm -n my-vms
----

出力例:
[source,text]
----
NAME            AGE   STATUS   READY
fedora-app-vm   14m   Paused   False
----

=== VM の再起動

再起動 (Restart) は、停止と起動を順番に実行します。以下の場合に使用します。

* 再起動が必要な設定変更を適用する場合
* ゲスト OS の問題から復旧する場合
* VM の状態をリフレッシュする場合

**Web コンソール:**

. VM の詳細ページに移動します。
. **Actions** -> **Restart** をクリックします。
+
image::vm-lifecycle-states/vm-running-restart-action.png[VM 詳細ページ。Actions メニューの Restart オプションを表示]

**CLI:**

[source,bash,role=execute]
----
virtctl restart fedora-app-vm -n my-vms
----

NOTE: 再起動は正常終了が完了するまで待機してから起動します。ゲスト OS が応答しない場合、再起動に時間がかかるか、最初に強制停止が必要になることがあります。

=== VM の削除

VM を削除する際、関連するストレージ (PVC/DataVolume) も削除するかどうかを選択できます。

**Web コンソール:**

. VM の詳細ページに移動します。
. **Actions** -> **Delete** をクリックします。
. 確認ダイアログで、ディスクを削除するかどうかを選択します。
. **Delete** をクリックします。
+
image::vm-lifecycle-states/vm-stopped-delete-action.png[VM 詳細ページ。Actions メニューの Delete オプションを表示]
+
image::vm-lifecycle-states/vm-delete-confirmation-dialog.png[Delete VirtualMachine 確認ダイアログ]

**CLI (VM を削除、ディスクを保持):**

[source,bash,role=execute]
----
oc delete vm fedora-app-vm -n my-vms
----

デフォルトでは、VM が所有する DataVolume は削除されます。これらを保持するには、最初に所有参照を削除するか、Web コンソールのオプションを使用してください。

**削除の確認:**

[source,bash,role=execute]
----
# VM は存在しないはずです
oc get vm fedora-app-vm -n my-vms

# PVC が保持されているか確認 (必要に応じて)
oc get pvc -n my-vms
----

出力例:
[source,text]
----
Error from server (NotFound): virtualmachines.kubevirt.io "fedora-app-vm" not found

No resources found in my-vms namespace.
----

WARNING: VM の削除は永続的な操作です。削除する前に、重要なデータのバックアップがあることを確認してください。

    "lastTransitionTime": "2026-03-05T17:10:11Z",
    "status": "True",
    "type": "Ready"

  {
    "message": "All of the VMI's DVs are bound and ready",

一般的な条件:

[cols="1,2",options="header"]

|AgentConnected
|QEMU guest agent が通信中

|Synchronized
|VM の設定が VMI と同期済み
|===

== 実行戦略 (Run Strategies)

実行戦略は、ライフサイクル全体を通じて VM が自動的にどのように動作するかを定義します。実行戦略は VM リソース内で設定され、VM が自動的に起動するか、停止後に再起動するか、停止状態を維持するかを決定します。

=== 利用可能な実行戦略

[cols="1,2,2",options="header"]
|===
|戦略 |動作 |ユースケース

|`Always`
|VM は自動的に起動し、何らかの理由 (ゲストによって開始されたシャットダウンを含む) で停止した場合は再起動します。
|常に稼働している必要がある本番ワークロード。

|`RerunOnFailure`
|VM は自動的に起動し、障害時のみ再起動します。ゲストによるシャットダウンの場合は VM は停止状態を維持します。
|クラッシュからは復旧しつつ、意図的なシャットダウンには従うことが必要なワークロード。

|`Manual`
|`virtctl` または Web コンソールから明示的に要求された場合のみ起動または停止します。
|開発/テスト用 VM、または特定のスケジュールが必要なワークロード。

|`Halted`
|VM は停止状態を維持します。起動コマンドは無視されます。
|一時的に廃止された VM、またはメンテナンスモード。
|===

=== 実行戦略の選択

この決定木を使用して、ワークロードに適した戦略を選択してください。

[source,text]
----
  VMは常に稼働している必要がありますか?
      │
      ├── はい ──► Always
      │           自動起動し、停止時には自動的に再起動します。
      │
      └── いいえ
           │
           クラッシュから自動的に復旧すべきですか?
               │
               ├── はい ──► RerunOnFailure
               │           障害発生時には再起動し、
               │           ゲスト側で開始されたシャットダウン時には停止状態を維持します。
               │
               └── いいえ
                    │
                    手動での開始・停止制御を行いますか?
                        │
                        ├── はい   ──► Manual
                        │             明示的にリクエストしたときにのみ、
                        │             開始および停止します。
                        │
                        └── いいえ ──► Halted
                                      VMは停止したままになります。
                                      メンテナンス中にVMを待機状態にしておく場合に使用します。
----

=== 実行戦略の設定

**VM の YAML:**

[source,yaml]
----
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: my-vm
spec:
  runStrategy: Always    # または RerunOnFailure、Manual、Halted
  template:
    # ... VM テンプレート spec
----

**Web コンソール経由:**

. VM の詳細ページに移動します。
. **YAML** タブをクリックします。
. `spec.runStrategy` フィールドを修正します。
. **Save** をクリックします。
+
image::vm-lifecycle-states/vm-yaml-run-strategy.png[VM YAML タブ。runStrategy フィールドを表示]

NOTE: `runStrategy` と非推奨の `running` フィールドを同時に使用することはできません。新規 VM には `runStrategy` を使用してください。

=== 実行戦略と手動コマンドの関係

`Always` または `RerunOnFailure` を使用する場合、以下の点に注意してください。

* `virtctl stop` は一時的に VM を停止しますが、自動的に再起動します。
* VM を停止状態に保つには、実行戦略を `Halted` または `Manual` に変更してください。
* ゲストによって開始されたシャットダウン (例: VM 内部での `shutdown -h now`) は、戦略に応じて異なる動作をします。

== まとめ

本モジュールでは以下を学びました。

* VirtualMachine リソースと VirtualMachineInstance リソースの違い
* VM ライフサイクルの状態と遷移 (状態遷移図を含む)
* VM の起動、停止、一時停止、再開、再起動、削除の方法
* Node drain やアップグレード時におけるライブマイグレーションと VM ライフサイクルの関係
* 条件 (Conditions) とイベント (Events) を使用した VM 状態の監視方法
* 実行戦略による VM の自動動作の制御と適切な戦略の選択方法
