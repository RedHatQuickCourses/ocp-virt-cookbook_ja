= デフォルト Storage Class の設定
:navtitle: ストレージ設定

== 概要

このチュートリアルでは、OpenShift Virtualization 用のデフォルト Storage Class を設定する方法を学習します。組み込みの DataSource イメージ (Fedora、RHEL、CentOS Stream、Windows) からブートソースを自動的にプロビジョニングするには、デフォルト Storage Class が必要です。これがない場合、DataSource は保留状態のままとなり、仮想マシン (VM) を作成できません。デフォルト Storage Class を設定すると、明示的な指定がない場合でも、仮想マシンやデータボリュームが指定したストレージを自動的に使用するようになるため、デプロイメントと管理が簡素化されます。

テスト済みのバージョン:

----
OpenShift 4.19、 4.20
----

== 前提条件

開始するには、以下のものが必要です。

* **OpenShift クラスター**: OpenShift Virtualization がインストールされた OpenShift クラスター
* **クラスター管理者のアクセス権**: cluster-admin 権限を持つクラスターへのアクセス権
* **Storage Class**: クラスター内に設定済みの Storage Class が少なくとも 1 つあること
* **ストレージプロビジョナー**: 動的プロビジョニングをサポートするストレージプロビジョナー

== ステップ 1: 利用可能な Storage Class の確認

まず、クラスター内で利用可能な Storage Class を確認し、既にデフォルトとして設定されている Storage Class があるかどうかを特定します。

[source,bash,role=execute]
----
oc get sc
----

このコマンドを実行すると、すべての Storage Class が名前とプロビジョナーとともに一覧表示されます。名前の横に `(default)` と表示されている Storage Class があれば、それが現在デフォルトとして設定されています。

デフォルト Storage Class が存在しない場合の出力例:

----
NAME                    PROVISIONER                             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
ceph-rbd-sc (default)   rbd.csi.ceph.com                        Delete          Immediate              true                   2d
hostpath-provisioner    kubevirt.io/hostpath-provisioner        Delete          WaitForFirstConsumer   false                  1d
local-storage           kubernetes.io/no-provisioner            Delete          WaitForFirstConsumer   false                  1d
----

既存のデフォルト Storage Class が存在する場合の出力例:

----
NAME                    PROVISIONER                             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
ceph-rbd-sc (default)   rbd.csi.ceph.com                        Delete          Immediate              true                   2d
hostpath-provisioner    kubevirt.io/hostpath-provisioner        Delete          WaitForFirstConsumer   false                  1d
local-storage           kubernetes.io/no-provisioner            Delete          WaitForFirstConsumer   false                  1d
----

以下の点を確認してください。

. デフォルトとして設定したい Storage Class の名前
. 既にデフォルト Storage Class が設定されているかどうか

== ステップ 2: 既存のデフォルトの削除 (必要な場合)

別の Storage Class が既にデフォルトとして設定されている場合は、新しいデフォルトを設定する前にそのアノテーションを削除する必要があります。1 つのクラスターには、デフォルト Storage Class を 1 つしか設定できません。

Storage Class からデフォルトのアノテーションを削除するには、以下を実行します。

[source,bash,role=execute]
----
oc annotate sc <the-old-default-storage-class-name> storageclass.kubernetes.io/is-default-class-
----

NOTE: アノテーションキーの末尾にあるハイフンが、アノテーションを削除する役割を果たします。

== ステップ 3: Storage Class へのアノテーション追加

選択した Storage Class にアノテーションを追加します。このアノテーションにより、その Storage Class をデフォルトとして使用するよう OpenShift に指示します。

アノテーションは以下の通りです: `storageclass.kubernetes.io/is-default-class: "true"`

[source,bash,role=execute]
----
oc annotate sc <your-storage-class-name> storageclass.kubernetes.io/is-default-class="true"
----

例えば、Storage Class 名が `ceph-rbd-sc` の場合:

[source,bash,role=execute]
----
oc annotate sc ceph-rbd-sc storageclass.kubernetes.io/is-default-class="true"
----

== ステップ 4: デフォルト Storage Class の確認

アノテーションを適用した後、変更が反映されたことを確認します。

[source,bash,role=execute]
----
oc get sc
----

デフォルト設定後の出力例:

----
NAME                    PROVISIONER                             RECLAIMPOLICY   VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION   AGE
ceph-rbd-sc (default)   rbd.csi.ceph.com                        Delete          Immediate              true                   2d
hostpath-provisioner    kubevirt.io/hostpath-provisioner        Delete          WaitForFirstConsumer   false                  1d
local-storage           kubernetes.io/no-provisioner            Delete          WaitForFirstConsumer   false                  1d
----

選択した Storage Class 名の横に `(default)` と表示されていることを確認してください。

== ステップ 5: デフォルト Storage Class のテスト

デフォルト Storage Class が正しく機能しているかを確認するためのテストを行います。Storage Class を指定せずに PVC を作成します。

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: test-default-storage
  namespace: default
spec:
  accessModes:
    - ReadWriteOnce
  resources:
    requests:
      storage: 1Gi
EOF
----

次に、PVC が正しい Storage Class で作成されたことを確認します。

[source,bash,role=execute]
----
oc get pvc test-default-storage -n default
----

出力例:

----
NAME                   STATUS    VOLUME   CAPACITY   ACCESS MODES   STORAGECLASS   AGE
test-default-storage   Pending                                      lvms-vg1       0s
----

PVC のステータスが `Pending` になっていますが、デフォルト Storage Class (この例では `lvms-vg1`) が自動的に割り当てられています。

=== ボリュームバインディングモードの理解

PVC が `Pending` ステータスのままになるのは、ほとんどの Storage Class で `WaitForFirstConsumer` ボリュームバインディングモードが使用されているためであり、想定動作です。

[cols="1,2,2"]
|===
|バインディングモード |動作 |使用ケース

|`WaitForFirstConsumer`
|PVC を使用する Pod がスケジュールされた時点で PV がプロビジョニングされる
|Pod と同じノード上にストレージを作成するため、トポロジー対応ストレージ (LVM、ローカルストレージ) に適している

|`Immediate`
|PVC が作成されるとすぐに PV がプロビジョニングされる
|どのノードからでもアクセス可能なネットワーク接続ストレージ (NFS、Ceph、クラウドストレージ) に適している
|===

Storage Class のバインディングモードを確認するには、以下を実行します。

[source,bash,role=execute]
----
oc get sc <storage-class-name> -o jsonpath='{.volumeBindingMode}'
----

== ステップ 6: デフォルトストレージを使用した VM のデプロイ

これで、デフォルト Storage Class をデータボリュームに使用する仮想マシンをデプロイできるようになりました。

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: test-vm-default-storage
  namespace: default
spec:
  runStrategy: Always
  dataVolumeTemplates:
  - metadata:
      name: test-vm-disk
    spec:
      pvc:
        accessModes:
        - ReadWriteOnce
        resources:
          requests:
            storage: 10Gi
      sourceRef:
        kind: DataSource
        name: fedora
        namespace: openshift-virtualization-os-images
  template:
    metadata:
      labels:
        kubevirt.io/vm: test-vm-default-storage
    spec:
      domain:
        devices:
          disks:
          - name: datavolumedisk
            disk:
              bus: virtio
        resources:
          requests:
            memory: 1Gi
            cpu: 1
      networks:
      - name: default
        pod: {}
      volumes:
      - name: datavolumedisk
        dataVolume:
          name: test-vm-disk
EOF
----

== トラブルシューティング

=== 一般的な問題

==== 複数のデフォルト Storage Class

複数の Storage Class がデフォルトとしてマークされている場合は、1 つを除いてすべてのアノテーションを削除してください。

[source,bash,role=execute]
----
oc get sc -o custom-columns=NAME:.metadata.name,DEFAULT:.metadata.annotations.storageclass\.kubernetes\.io/is-default-class
----

==== Storage Class が見つからない

Storage Class にアノテーションを付ける前に、それが存在することを確認してください。

[source,bash,role=execute]
----
oc get sc <storage-class-name>
----

==== 権限拒否 (Permission Denied)

cluster-admin 権限を持っていることを確認してください。

[source,bash,role=execute]
----
oc auth can-i create storageclass --all-namespaces
----

=== 確認コマンド

すべての Storage Class とデフォルトステータスを確認します。

[source,bash,role=execute]
----
oc get sc -o wide
----

特定の Storage Class の詳細情報を表示します。

[source,bash,role=execute]
----
oc describe sc <storage-class-name>
----

PVC の一覧とその Storage Class を表示します。

[source,bash,role=execute]
----
oc get pvc --all-namespaces -o custom-columns=NAMESPACE:.metadata.namespace,NAME:.metadata.name,STORAGECLASS:.spec.storageClassName
----

== ベストプラクティス

. **適切なストレージの選択**: 仮想マシンに必要なパフォーマンスと機能 (高速な I/O、スナップショット、暗号化など) を提供する Storage Class を選択してください。
. **ワークロード要件の検討**: ワークロードによって必要なストレージ特性が異なる場合があります。デフォルトに頼るだけでなく、重要なワークロードに対しては特定の Storage Class を使用することを検討してください。
. **ストレージ使用量の監視**: デフォルト Storage Class がニーズを満たしていることを確認するため、ストレージの使用量とパフォーマンスを定期的に監視してください。
. **選択の文書化**: 今後の参考およびトラブルシューティングのために、なぜその Storage Class をデフォルトとして選択したのかを文書化してください。

== まとめ

このチュートリアルでは、以下の内容を学習しました。

* 利用可能な Storage Class を表示し、既存のデフォルトを特定する方法
* 既存のデフォルト Storage Class のアノテーションを削除する方法
* `storageclass.kubernetes.io/is-default-class` を使用して Storage Class をデフォルトとしてアノテーションする方法
* テスト PVC の作成と VM のデプロイによるデフォルト Storage Class の検証方法
