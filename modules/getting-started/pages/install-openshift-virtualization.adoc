= OpenShift Virtualization Operator のインストールと設定
:navtitle: OpenShift Virtualization のインストール

== 概要

このチュートリアルでは、OpenShift クラスター上でコンテナワークロードと並行して仮想マシンを実行できるようにする、OpenShift Virtualization Operator のインストールおよび設定方法を説明します。OpenShift Virtualization は、アップストリームの KubeVirt プロジェクトをベースにしており、エンタープライズグレードの仮想化機能を提供します。

* <<Web コンソールを使用したインストール>>
* <<コマンドラインを使用したインストール>>

== 前提条件

* **OpenShift 4.18+**: サポートされているプラットフォーム上でインストールおよび実行されていること
* **クラスター管理者権限**: Operator のインストールおよびクラスターリソースの設定に必要

検証済みバージョン:
----
OpenShift 4.18, 4.19, 4.20, 4.21
----

== ハードウェアおよびソフトウェアの要件

OpenShift Virtualization をインストールする前に、クラスターがハードウェア、オペレーティングシステム、ストレージ、ネットワークの要件を満たしていることを確認してください。

CPU 仕様、サポート対象プラットフォーム、ストレージに関する考慮事項、リソースオーバーヘッドなどの詳細な要件については、link:https://docs.redhat.com/en/documentation/openshift_container_platform/latest/html/virtualization/installing#virt-preparing-cluster-for-virt_preparing-cluster-for-virt[OpenShift Virtualization 用のクラスターの準備,window=_blank]を参照してください。

TIP: ストレージ設定については、 Operator のインストール完了後に xref:default-storage-class.adoc[] を参照してください。

== Web コンソールを使用したインストール

Web コンソールを使用すると、OpenShift Virtualization のインストールをガイド付きで実行できます。

=== ステップ 1: OperatorHub へのアクセス

. `cluster-admin` 権限を持つユーザーとして OpenShift Web コンソールにログインします。
. ** Operators** -> ** OperatorHub** に移動します。
+
image::install-1-software-catalog.png[OpenShift Web コンソールの OperatorHub]

. **Filter by keyword** フィールドに `Virtualization` と入力します。
+
image::install-2-find-openshift-virtualization.png[ OperatorHub で OpenShift Virtualization をフィルタリング]

=== ステップ 2: Operator のインストール

. **Red Hat** ソースラベルが付いた **OpenShift Virtualization** タイルを選択します。
. Operator 情報を確認し、**Install** をクリックします。
+
image::install-3-click-install.png[インストールボタンが表示された OpenShift Virtualization Operator の詳細]

. Install Operator ページで、デフォルト設定のまま **Install** をクリックします。
+
image::install-4-let-default-click-install.png[デフォルト設定の Install Operator ページ]

IMPORTANT: 手動承認 (Manual approval) も利用可能ですが、サポートされていないバージョンの組み合わせを実行するリスクがあるため推奨されません。影響を完全に理解している場合にのみ、Manual を選択してください。

[start=4]
. Operator のインストールが完了するまで待ちます。
+
image::install-5-wait-for-install-ready.png[ Operator のインストール進行状況]

=== ステップ 3: HyperConverged リソースの作成

. Operator のインストールが完了したら、**Create HyperConverged** をクリックします。
+
image::install-6-create-hyperconverged.png[ Operator インストール後の Create HyperConverged ボタン]

. デフォルト設定のまま、一番下までスクロールします。
+
image::install-7-let-default-roll-to-the-bottom.png[デフォルト設定の HyperConverged 設定]

. **Create** をクリックして、OpenShift Virtualization をデプロイします。
+
image::install-8-click-create.png[HyperConverged リソースの作成ボタン]

=== ステップ 4: インストールの確認

すべての条件が成功と報告されるまで待ちます。HyperConverged リソースのステータスでデプロイの進行状況を確認できます。

image::install-9-wait-for-conditions.png[デプロイ成功を示す HyperConverged 条件]

完了すると、 Operators リストにインストール済みとして表示されます。

image::install-10-installed-operator.png[インストール済みの OpenShift Virtualization Operator]

== コマンドラインを使用したインストール

自動デプロイや Web コンソールにアクセスできない環境では、CLI によるインストール方法を使用します。

=== ステップ 1: Namespace、 OperatorGroup、Subscription の作成

必要なすべてのリソースを含む単一のマニフェストファイルを作成します。

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: v1
kind: Namespace
metadata:
  name: openshift-cnv
---
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: kubevirt-hyperconverged-group
  namespace: openshift-cnv
spec:
  targetNamespaces:
  - openshift-cnv
---
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: hco-operatorhub
  namespace: openshift-cnv
spec:
  source: redhat-operators
  sourceNamespace: openshift-marketplace
  name: kubevirt-hyperconverged
  channel: stable
  installPlanApproval: Automatic
EOF
----

=== ステップ 2: Operator インストールの確認

Operator がインストールされるのを待ち、ステータスを確認します。

[source,bash,role=execute]
----
# Watch the CSV status until it shows Succeeded
oc get csv -n openshift-cnv -w
----

インストール完了時に期待される出力:

----
NAME                                       DISPLAY                    VERSION   REPLACES                                   PHASE
kubevirt-hyperconverged-operator.v4.20.3   OpenShift Virtualization   4.20.3    kubevirt-hyperconverged-operator.v4.20.1   Succeeded
----

`Succeeded` と表示されたら `Ctrl+C` を押して監視を停止します。

=== ステップ 3: HyperConverged リソースの作成

HyperConverged カスタムリソースをデプロイして、インストールを完了します。

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: hco.kubevirt.io/v1beta1
kind: HyperConverged
metadata:
  name: kubevirt-hyperconverged
  namespace: openshift-cnv
spec:
EOF
----

NOTE: 上記の最小限の HyperConverged スペックは、すべてのデフォルト設定を使用します。高度な設定オプションについては、https://docs.openshift.com/container-platform/latest/virt/install/installing-virt.html#virt-customizing-storage-profile_installing-virt[公式ドキュメント,window=_blank] を参照してください。

=== ステップ 4: インストール完了の待機

HyperConverged リソースが使用可能になるまで待ちます。

[source,bash,role=execute]
----
oc wait hyperconverged kubevirt-hyperconverged -n openshift-cnv --for=condition=Available --timeout=15m
----

インストールには通常 5〜10 分かかります。

=== ステップ 5: インストールの確認

すべての条件が正常であることを確認します。

[source,bash,role=execute]
----
oc get hyperconverged kubevirt-hyperconverged -n openshift-cnv -o jsonpath='{range .status.conditions[*]}{.type}: {.status}{"\n"}{end}'
----

インストール完了時の期待される出力:

----
ReconcileComplete: True
Available: True
Progressing: False
Degraded: False
Upgradeable: True
----

== OpenShift Virtualization のアンインストール

OpenShift Virtualization をクラスターから削除する必要がある場合は、以下の手順を順番に実行してください。アンインストールプロセスでは、すべての仮想化コンポーネントが安全に停止されるため数分かかります。

IMPORTANT: Operator のサブスクリプションを削除するだけでは、デプロイされたリソースは削除されません。すべてのコンポーネントを適切にクリーンアップするには、まず HyperConverged リソースを削除する必要があります。

=== ステップ 1: すべての仮想マシンの削除

アンインストール前に、すべての VM が停止および削除されていることを確認してください。

[source,bash,role=execute]
----
# List all VMs across namespaces
oc get vm -A

# Delete VMs (repeat for each namespace)
oc delete vm --all -n <namespace>
----

WARNING: 実行中の VM は、アンインストール中に強制終了されます。

=== ステップ 2: HyperConverged リソースの削除

このステップで、すべての OpenShift Virtualization コンポーネントが削除されます。

[source,bash,role=execute]
----
oc delete hyperconverged kubevirt-hyperconverged -n openshift-cnv
----

クリーンアップの進行状況を監視します。

[source,bash,role=execute]
----
# Watch pods being terminated (this may take 5-10 minutes)
oc get pods -n openshift-cnv -w
----

すべての Pod が終了するまで待機してから次に進みます。

=== ステップ 3: Operator のサブスクリプションと CSV の削除

[source,bash,role=execute]
----
# Delete the subscription
oc delete subscription hco-operatorhub -n openshift-cnv

# Delete the ClusterServiceVersion
oc delete csv -n openshift-cnv -l operators.coreos.com/kubevirt-hyperconverged.openshift-cnv
----

=== ステップ 4: Namespace の削除 (オプション)

完全にクリーンアップするために、Namespace を削除します。

[source,bash,role=execute]
----
oc delete namespace openshift-cnv
----

=== ステップ 5: クリーンアップの確認

すべてのリソースが削除されたことを確認します。

[source,bash,role=execute]
----
# Should return empty or "No resources found"
oc get pods -n openshift-cnv
oc get csv -n openshift-cnv
----
