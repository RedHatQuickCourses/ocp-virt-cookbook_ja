= QEMU ゲストエージェントのインストール
:navtitle: QEMU ゲストエージェントのインストール
:page-toclevels: 3

== 概要

このチュートリアルでは、さまざまな Linux ディストリビューションに qemu-guest-agent をインストールする方法を説明します。QEMU ゲストエージェントは、ゲスト OS 内で実行されるデーモンです。これにより、アプリケーション整合性のあるスナップショット、ゲスト OS、ファイルシステムのレポート、動的な SSH 鍵およびパスワードのインジェクション、IP アドレスのレポート、exec/ping ヘルスプローブなどが可能になります。

=== 学習内容

* Fedora、Debian、および openSUSE Leap で `virtctl console` を使用して `qemu-guest-agent` を手動でインストールおよび有効化する方法
* cloud-init の `packages` および `runcmd` モジュールを使用して `qemu-guest-agent` を自動的にインストールする方法
* エージェントが接続され、ゲスト OS 情報を OpenShift Virtualization にレポートしていることを確認する方法

== 前提条件

* OpenShift Virtualization Operator がインストールされた **OpenShift {ocp-min-version}+** (xref:install-openshift-virtualization.adoc[OpenShift Virtualization のインストール] を参照)
* CLI ツール: `oc`、`virtctl`、`yq`

== namespace の設定

このチュートリアルで使用するすべての仮想マシンを配置する namespace を作成します。

[source,bash,role=execute]
----
oc create namespace qemu-ga-demo
----

[source,bash,role=execute]
----
oc project qemu-ga-demo
----

== `virtctl console` を使用したインストール

このセクションでは、`virtctl console <vm-name>` を使用して仮想マシンのコンソールに接続し、cloud-init で作成されたユーザーとしてログインし、ディストリビューションのパッケージマネージャーを使用して `qemu-guest-agent` をインストールし、`systemctl enable --now qemu-guest-agent` を実行してサービスを起動するとともに再起動後も有効になるよう設定します。

WARNING: 以下の例で使用されている cloud-init のパスワードはデモ目的のみのものです。本番環境では、常に強力で一意のパスワードまたは SSH 鍵認証を使用してください。

=== Fedora/RHEL

==== ステップ 1: Fedora 仮想マシンの作成

CLI から仮想マシンを作成します。 (Web コンソールから作成する場合は <<fedora-create-web-console,こちら>> をクリック)

NOTE: containerdisk の代わりに datavolume を使用しています。これにより初回の起動時間は長くなりますが、ルートボリュームが PVC に保存されるため、virt-launcher がクラッシュした場合や、仮想マシンを停止して再起動した場合でも、以降の手順での変更が永続化されるという利点があります。

xref:attachment$installing-qemu-guest-agent/fedora-no-qga.yaml[fedora-no-qga.yaml のダウンロード]

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
 name: fedora-virtctl
 namespace: qemu-ga-demo
spec:
 runStrategy: Always
 dataVolumeTemplates:
  - metadata:
    name: fedora-virtctl-rootdisk
   spec:
    storage:
     resources:
      requests:
       storage: 10Gi
     accessModes:
      - ReadWriteOnce
    source:
     registry:
      url: docker://quay.io/ocpv_cookbook/fedora-no-qga:latest
 template:
  metadata:
   labels:
    app: fedora-virtctl
  spec:
   domain:
    cpu:
     cores: 2
    memory:
     guest: 4Gi
    devices:
     disks:
      - name: rootdisk
       disk:
        bus: virtio
      - name: cloudinitdisk
       disk:
        bus: virtio
   volumes:
    - name: rootdisk
     dataVolume:
      name: fedora-virtctl-rootdisk
    - name: cloudinitdisk
     cloudInitNoCloud:
      userData: |-
       #cloud-config
       user: fedora
       password: fedora
       chpasswd: { expire: false }
EOF
----

仮想マシンの STATUS が `Running` になるまで待ちます。

[source,bash,role=execute]
----
oc get vm fedora-virtctl -w
----

TIP: `-w` フラグは継続的に監視します。STATUS が `Running` と表示されたら `Ctrl+C` を押します。

[source,bash]
----
# 出力例
NAME        AGE  STATUS  READY
fedora-virtctl      6h8m  Running  True
----

<<fedora-step-2, ステップ 2>> に進みます

[#fedora-create-web-console]
Web コンソールから仮想マシンを作成します。

. **Virtualization** -> **VirtualMachines** に移動します
. 右上にある `Create` ボタンの横のドロップダウンをクリックします
. `With YAML` を選択します
. テキストエディターウィンドウ内のすべてを選択して削除します
. 上記の YAML を貼り付けます
. 左下の `Create` をクリックします

新しく作成した VM の「Overview」タブにリダイレクトされます。Status が `Running` になるまで待ちます。

[#cloud-init-ga-install]
== cloud-init の `packages` および `runcmd` モジュールを使用したインストール

cloud-init の `packages` モジュールを使用すると、ブートプロセス中にパッケージをインストールできます。このセクションでは、これを使用して `qemu-guest-agent` パッケージをインストールします。インストールが完了すると、cloud-init の `runcmd` モジュールが `systemctl enable --now qemu-guest-agent` を実行し、ブート中にサービスを起動して有効化します。

WARNING: 以下の例の cloud-init パスワードはデモ目的専用です。本番環境では、常に強力で一意なパスワードまたは SSH 鍵認証を使用してください。

=== Fedora/RHEL

仮想マシンを作成します。

xref:attachment$installing-qemu-guest-agent/fedora-qga-package.yaml[fedora-qga-package.yaml をダウンロード]

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
 name: fedora-cloudinit
 namespace: qemu-ga-demo
spec:
 runStrategy: Always
 dataVolumeTemplates:
  - metadata:
    name: fedora-cloudinit-rootdisk
   spec:
    storage:
     resources:
      requests:
       storage: 10Gi
     accessModes:
      - ReadWriteOnce
    source:
     registry:
      url: docker://quay.io/ocpv_cookbook/fedora-no-qga:latest
 template:
  metadata:
   labels:
    app: fedora-cloudinit
  spec:
   domain:
    cpu:
     cores: 2
    memory:
     guest: 4Gi
    devices:
     disks:
      - name: rootdisk
       disk:
        bus: virtio
      - name: cloudinitdisk
       disk:
        bus: virtio
   volumes:
    - name: rootdisk
     dataVolume:
      name: fedora-cloudinit-rootdisk
    - name: cloudinitdisk
     cloudInitNoCloud:
      userData: |-
       #cloud-config
       user: fedora
       password: fedora
       chpasswd: { expire: false }
       packages: # <.>
        - qemu-guest-agent
       runcmd: # <.>
        - systemctl enable --now qemu-guest-agent # <.>
EOF
----

<.> **packages** cloud-init モジュールを使用して `qemu-guest-agent` をインストールします
<.> **runcmd** cloud-init モジュールを使用して起動中に任意のコマンドを実行します
<.> パッケージのインストール後に `systemctl enable --now qemu-guest-agent` を実行してサービスを開始します

fedora-cloudinit  8m23s  Running  True

検証コマンドがこの仮想マシンに対して機能するように、`VM_NAME` 変数を設定します:

エージェントが接続され、OCP-Virt にレポートしていることを確認するために、<<verify-qga-reporting>> に進みます。

=== Debian

cloud-init の `packages` および `runcmd` 設定は、上記の Fedora の例と同じです。唯一の違いは、コンテナイメージ、ユーザー名、VM 名です。

仮想マシンを作成します。

xref:attachment$installing-qemu-guest-agent/debian-qga-package.yaml[debian-qga-package.yaml のダウンロード]

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
 name: debian-cloudinit
 namespace: qemu-ga-demo
spec:
 runStrategy: Always
 dataVolumeTemplates:
  - metadata:
    name: debian-cloudinit-rootdisk
   spec:
    storage:
     resources:
      requests:
       storage: 10Gi
     accessModes:
      - ReadWriteOnce
    source:
     registry:
      url: docker://quay.io/ocpv_cookbook/debian-no-qga:latest
 template:
  metadata:
   labels:
    app: debian-cloudinit
  spec:
   domain:
    cpu:
     cores: 2
    memory:
     guest: 4Gi
    devices:
     disks:
      - name: rootdisk
       disk:
        bus: virtio
      - name: cloudinitdisk
       disk:
        bus: virtio
   volumes:
    - name: rootdisk
     dataVolume:
      name: debian-cloudinit-rootdisk
    - name: cloudinitdisk
     cloudInitNoCloud:
      userData: |-
       #cloud-config
       user: debian
       password: debian
       chpasswd: { expire: false }
       packages:
        - qemu-guest-agent
       runcmd:
        - systemctl enable --now qemu-guest-agent
EOF
----

仮想マシンの STATUS が `Running` になるまで待ちます。

[source,bash,role=execute]
----
oc get vm debian-cloudinit -w
----

TIP: `-w` フラグは継続的に監視します。STATUS が `Running` と表示されたら `Ctrl+C` を押します。

[source,bash]
----
# 出力例
NAME       AGE   STATUS  READY
debian-cloudinit 5m31s  Running  True
----

検証コマンドがこの VM に対して機能するように、`VM_NAME` 変数を設定します。

[source,bash,role=execute]
----
VM_NAME=debian-cloudinit
----

エージェントが接続され、OCP-Virt にレポートを送信していることを確認するには、<<verify-qga-reporting>> に進みます。

[#verify-qga-reporting]
== `qemu-guest-agent` が OCP-Virt にレポートしていることの確認

Web コンソールから、または `oc` および `virtctl` CLI ツールを使用してターミナルから、qemu-guest-agent が動作し、ゲスト OS に関する情報を OCP-Virt に適切にレポートしているかを確認する方法はいくつかあります。

=== ターミナルからの確認

`AgentConnected` 条件が `True` であることを確認します。

[source,bash,role=execute]
----
oc get vm $VM_NAME -oyaml | yq -e '.status.conditions[] | select(.type == "AgentConnected")'
----

成功した場合の出力は次のようになります。

[source,yaml]
----
# 出力例
lastProbeTime: "2026-06-04T13:33:28Z"
lastTransitionTime: null
status: "True"
type: AgentConnected
----

guest-agent が VM の IP アドレスを報告していることを確認します。

[source,bash,role=execute]
----
oc get vmi $VM_NAME -oyaml | yq -e '.status.interfaces[]'
----

[source,bash]
----
# 出力例
infoSource: domain, guest-agent # <1>
interfaceName: enp1s0
ipAddress: 10.130.0.22
ipAddresses:
 - 10.130.0.22
linkState: up
mac: 0a:58:0a:82:00:16
name: default
podInterfaceName: eth0
queueCount: 1
----

<1> infoSource として `guest-agent` が存在する場合、IP アドレスが qemu-guest-agent によって報告されていることを示します。

詳細なゲスト OS 情報を取得します。

[source,bash,role=execute]
----
virtctl guestosinfo $VM_NAME
----

=== OCP-Virt Web コンソールによる検証

. **Virtualization** -> **VirtualMachines** に移動します。
. 仮想マシンをクリックします。

**Overview** タブで、qemu-guest-agent がゲスト OS 情報をレポートしていることを確認できます。

image::qemu-guest-agent/Web-console-OS-report.png[web console os reporting]

**Diagnostics** タブで、仮想マシンの `AgentConnected` の **status** が `True` になっていることを確認できます。

image::qemu-guest-agent/Web-console-AgentConnected.png[AgentConnected]

== まとめ

このチュートリアルでは、次の方法を学びました:

* Fedora、Debian、および openSUSE Leap 上で `virtctl console` を使用して手動で `qemu-guest-agent` をインストールおよび有効化する
* cloud-init の `packages` および `runcmd` モジュールを使用して `qemu-guest-agent` を自動的にインストールする
* エージェントが接続され、ゲスト OS 情報を OpenShift Virtualization に報告していることを確認する
