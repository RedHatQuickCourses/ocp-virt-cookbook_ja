= 実行中の VM へのボリュームおよびネットワークインターフェースのホットプラグ
:navtitle: ボリュームとインターフェースのホットプラグ

== 概要

このチュートリアルでは、仮想マシンを再起動することなく、ストレージボリュームを動的に追加および削除する方法を説明します。ホットプラグ機能により、ダウンタイムなしでのストレージ拡張、柔軟なリソース割り当て、メンテナンス時間の短縮が可能になります。

`virtctl addvolume` を使用して新しい PVC を実行中の VM にアタッチし、ゲスト OS 内部で新しいブロックデバイスとして認識されることを確認した後、`virtctl removevolume` を使用して削除します。また、ネットワークインターフェースのホットプラグに関する概念と要件についても解説します。

== 前提条件

* **OpenShift 4.18 以上** (OpenShift Virtualization Operator がインストール済みであること) 
* **クラスター管理者権限** (`system:admin` または同等の権限)
* **`oc` CLI** および **`virtctl` CLI** がインストール済みであること
* **default StorageClass** が設定済みであること

テスト済みのバージョン:
----
OpenShift 4.20, 4.21
----

== 手順 1: namespace とベース VM の作成

namespace を作成し、ホットプラグのターゲットとなる VM をデプロイします。

[source,bash,role=execute]
----
oc create namespace hotplug-demo
----

WARNING: この例で使用している cloud-init のパスワードはデモ用です。本番環境では、常に強力で一意のパスワードを使用するか、SSH 鍵認証を使用してください。

xref:attachment$hotplug-volumes-interfaces/vm-hotplug.yaml[vm-hotplug.yaml をダウンロード]

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: hotplug-vm
  namespace: hotplug-demo
spec:
  runStrategy: Always
  template:
    metadata:
      labels:
        kubevirt.io/domain: hotplug-vm
    spec:
      domain:
        devices:
          disks:
          - name: rootdisk
            disk:
              bus: virtio
          - name: cloudinitdisk
            disk:
              bus: virtio
          interfaces:
          - name: default
            masquerade: {}
        resources:
          requests:
            memory: 1Gi
      networks:
      - name: default
        pod: {}
      volumes:
      - name: rootdisk
        containerDisk:
          image: quay.io/containerdisks/fedora:latest
      - name: cloudinitdisk
        cloudInitNoCloud:
          userData: |
            #cloud-config
            password: redhat
            chpasswd:
              expire: false
EOF
----

VM が起動するまで待ちます。

[source,bash,role=execute]
----
oc get vm -n hotplug-demo -w
----

`STATUS=Running` かつ `READY=True` になったら次へ進みます。`Ctrl+C` を押して監視を終了してください。

初期のディスク構成を確認します。

[source,bash,role=execute]
----
oc get vmi hotplug-vm -n hotplug-demo -o jsonpath='{range .status.volumeStatus[*]}{.name}: {.target}{"\n"}{end}'
----

期待される出力:
----
rootdisk: vda
cloudinitdisk: vdb
----

== 手順 2: ホットプラグ用の PVC を作成

実行中の VM にホットプラグする PersistentVolumeClaim を作成します。

xref:attachment$hotplug-volumes-interfaces/hotplug-pvc.yaml[hotplug-pvc.yaml をダウンロード]

[source,bash,role=execute]
----
oc apply -f - <<EOF
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: hotplug-disk
  namespace: hotplug-demo
spec:
  accessModes:
  - ReadWriteOnce
  resources:
    requests:
      storage: 5Gi
  storageClassName: lvms-vg1
  volumeMode: Block
EOF
----

IMPORTANT: ホットプラグするボリュームは `volumeMode: Block` である必要があります。Filesystem モードの PVC は事前に作成された `disk.img` ファイルを必要とし、空のボリュームの直接的なホットプラグには適していません。

PVC がプロビジョニングされるのを待ちます。`WaitForFirstConsumer` binding mode の場合、アタッチされるまで `Pending` のままになることがあります。

[source,bash,role=execute]
----
oc get pvc hotplug-disk -n hotplug-demo
----

== 手順 3: ボリュームのホットプラグ

`virtctl addvolume` を使用して、実行中の VM に PVC をアタッチします。

[source,bash,role=execute]
----
virtctl addvolume hotplug-vm --volume-name=hotplug-disk --namespace=hotplug-demo --persist
----

期待される出力:
----
Successfully submitted addvolume request to VM hotplug-vm for volume hotplug-disk
----

`--persist` フラグを指定することで、VM が再起動してもボリュームがアタッチされたままになります。このフラグがない場合、次回の再起動時にボリュームはデタッチされます。

== 手順 4: ホットプラグされたボリュームの確認

VMI のボリュームステータスを確認し、新しいディスクが表示されていることを確認します。

[source,bash,role=execute]
----
oc get vmi hotplug-vm -n hotplug-demo -o jsonpath='{range .status.volumeStatus[*]}{.name}: {.target} (hotplugVolume: {.hotplugVolume}){"\n"}{end}'
----

期待される出力:
----
rootdisk: vda (hotplugVolume: )
cloudinitdisk: vdb (hotplugVolume: )
hotplug-disk: sda (hotplugVolume: {"attachPodName":"...","attachPodUID":"..."})
----

ホットプラグされたボリュームは、フェーズ `Ready` の SCSI デバイス (`sda`) として表示されます。`hotplugVolume` フィールドにアタッチ Pod の情報が含まれていることに注意してください。

PVC がバインドされていることを確認します。

[source,bash,role=execute]
----
oc get pvc hotplug-disk -n hotplug-demo
----

期待される出力:
----
NAME           STATUS   VOLUME       CAPACITY   ACCESS MODES   STORAGECLASS   AGE
hotplug-disk   Bound    pvc-xxxx     5Gi        RWO            lvms-vg1       1m
----

ゲスト OS 内部から確認します。VM コンソールにアクセスします。

[source,bash,role=execute]
----
virtctl console hotplug-vm -n hotplug-demo
----

ユーザー名 `fedora` とパスワード `redhat` でログインし、ブロックデバイスの一覧を表示します。

[source,bash]
----
lsblk
----

PVC のサイズと一致する新しいディスクデバイス (例: `sda`) が表示されるはずです。`Ctrl+]` を押して終了します。

== 手順 5: ホットプラグしたディスクのフォーマットと使用 (ゲスト内部) 

VM コンソール内で、新しいディスクをフォーマットします。

[source,bash]
----
sudo mkfs.xfs /dev/sda
----

マウントポイントを作成し、ディスクをマウントします。

[source,bash]
----
sudo mkdir -p /mnt/hotplug
sudo mount /dev/sda /mnt/hotplug
----

テストファイルを作成し、内容を確認します。

[source,bash]
----
echo "Hotplug test" | sudo tee /mnt/hotplug/test.txt
----

[source,bash]
----
cat /mnt/hotplug/test.txt
----

期待される出力:
----
Hotplug test
----

削除する前にアンマウントします。

[source,bash]
----
sudo umount /mnt/hotplug
----

`Ctrl+]` を押してコンソールから抜けます。

== 手順 6: ホットプラグされたボリュームの削除

実行中の VM からボリュームをデタッチします。

[source,bash,role=execute]
----
virtctl removevolume hotplug-vm --volume-name=hotplug-disk --namespace=hotplug-demo
----

期待される出力:
----
Successfully submitted removevolume request to VM hotplug-vm for volume hotplug-disk
----

IMPORTANT: データ破損を防ぐため、ホットプラグしたボリュームを削除する前に、必ずゲスト内部でファイルシステムをアンマウントしてください。

ボリュームが削除されたことを確認します。

[source,bash,role=execute]
----
oc get vmi hotplug-vm -n hotplug-demo -o jsonpath='{range .status.volumeStatus[*]}{.name}: {.target}{"\n"}{end}'
----

期待される出力:
----
rootdisk: vda
cloudinitdisk: vdb
----

`hotplug-disk` は接続解除されました。PVC 自体は存在し続け、データも保持されます。

[source,bash,role=execute]
----
oc get pvc hotplug-disk -n hotplug-demo
----

== ホットプラグボリュームの参考情報

=== --persist フラグ

[cols="1,1",options="header"]
|===
| フラグ
| 動作

| `--persist`
| ボリュームが VM spec に追加され、再起動後も維持されます

| (フラグなし)
| 現在の VMI にのみアタッチされます (再起動時に失われます) 
|===

永続的に接続する必要があるデータディスクには `--persist` を使用してください。データ移行や一度限りのインポートなどの一時的な操作には、フラグを省略します。

=== サポートされているボリュームタイプ

ホットプラグは以下をサポートしています:

* PersistentVolumeClaims (PVCs)
* DataVolumes

ホットプラグは以下をサポートしていません:

* containerDisk ボリューム
* cloudInitNoCloud / cloudInitConfigDrive ボリューム
* emptyDir ボリューム

=== ディスクバスタイプ

ホットプラグされたボリュームはデフォルトで SCSI バスを使用します (`sda`、`sdb` などとして表示されます) 。これは、virtio ディスクは起動後に PCI バスへホットプラグできないためです。SCSI はホットアド機能を提供します。

== ネットワークインターフェースのホットプラグ (リファレンス) 

OpenShift Virtualization はネットワークインターフェースのホットプラグもサポートしています。これには、すべてのクラスターで利用可能とは限らない追加のインフラストラクチャが必要です。

=== 要件

* **Multus CNI thick plugin**: 標準の Multus デプロイメントが thick plugin として実行されている必要があります。
* **Multus Dynamic Networks Controller**: アノテーションの変更を監視し、Multus に新しいアタッチメントの設定をトリガーするデーモン。
* **Multi-node cluster**: Single Node Cluster では、マイグレーションベースのホットプラグは利用できません。

=== 動作の仕組み

ボリュームのホットプラグ (`virtctl addvolume` を使用) とは異なり、ネットワークインターフェースのホットプラグは VM spec を編集することで行われます。

. セカンダリネットワーク用の NetworkAttachmentDefinition (NAD) を作成します。
. VM spec を編集して、新しいインターフェースとネットワークの定義を追加します。
. インターフェースは、実行中の VM に (thick Multus が利用可能な場合) アタッチされるか、ライブマイグレーション後にアタッチされます。

=== インターフェースの削除

VM spec でインターフェースの `state: absent` を設定します。

[source,yaml]
----
interfaces:
- name: dyniface1
  state: absent
  bridge: {}
----

NOTE: ホットアンプラグは、bridge バインディングのインターフェースでのみサポートされています。SR-IOV インターフェースはホットアンプラグできません。

ネットワークホットプラグの詳細手順については、link:https://kubevirt.io/user-guide/network/hotplug_interfaces/[KubeVirt Hotplug Network Interfaces documentation,window=_blank]を参照してください。

== クリーンアップ

このチュートリアルで作成したすべてのリソースを削除します。

[source,bash,role=execute]
----
oc delete namespace hotplug-demo
----

== まとめ

このチュートリアルでは、以下の方法を学びました。

* `virtctl addvolume` を使用して、実行中の VM に PVC ボリュームをホットプラグする
* `--persist` フラグを使用して、ホットプラグされたボリュームを再起動後も維持させる
* ホットプラグされたボリュームがゲスト OS 内部で新しいブロックデバイスとして認識されることを確認する
* VM 内部でホットプラグされたストレージをフォーマットおよびマウントする
* `virtctl removevolume` を使用して、ホットプラグされたボリュームを削除する
* ネットワークインターフェースのホットプラグに必要な要件と手法を理解する
