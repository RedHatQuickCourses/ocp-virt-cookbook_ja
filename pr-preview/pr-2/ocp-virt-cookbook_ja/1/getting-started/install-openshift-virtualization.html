OpenShift Virtualization Operator のインストールと設定

概要

このチュートリアルでは、OpenShift クラスター上でコンテナワークロードと並行して仮想マシンを実行できるようにする、OpenShift Virtualization Operator のインストールおよび設定方法を説明します。OpenShift Virtualization は、アップストリームの KubeVirt プロジェクトをベースにしており、エンタープライズグレードの仮想化機能を提供します。

  • Web コンソールを使用したインストール

  • コマンドラインを使用したインストール

OpenShift Virtualization を使用する理由

インストールに進む前に、OpenShift 上で仮想マシンを実行するビジネス上の動機を理解しておくと役立ちます。

インフラストラクチャーの統合

コンピュート、ストレージ、ネットワークのリソースを共有しながら、同じ OpenShift クラスター上で VM とコンテナを実行します。これにより、個別のハイパーバイザープラットフォームが不要になり、ハードウェアコストとライセンスコストが削減されます。

VMware の移行パス

Migration Toolkit for Virtualization (MTV) を使用すると、組織は既存の VMware vSphere VM を OpenShift Virtualization に移行できます。これにより、アプリケーションを書き直すことなく段階的な移行パスが提供され、コールド移行とウォーム移行の両方の戦略がサポートされます。

モダナイゼーションへの架け橋

レガシーな VM ワークロードの実行を継続しながら、アプリケーションをコンテナへとモダナイズします。Kubernetes を導入したものの、コンテナ化できないワークロードを保持しているチームは、両方を単一のプラットフォームで管理できます。

統合管理

単一のコントロールプレーンで VM とコンテナの両方を処理します。OpenShift RBAC、モニタリング (Prometheus)、ロギング、ネットワークポリシーがすべてのワークロードタイプに一律に適用されます。Web コンソールは、VM とコンテナを並べて管理するための単一のインターフェースを提供します。

デプロイされるコンポーネント

OpenShift Virtualization Operator をインストールすると、クラスター全体に連携する一連のコンポーネントがデプロイされます。このアーキテクチャーを理解することは、トラブルシューティングやキャパシティープランニングに役立ちます。

OpenShift Cluster
│
└─ openshift-cnv Namespace
   └─ HyperConverged CR (単一のエントリーポイント)
      ├─ KubeVirt Operator
      │    ├─ virt-api        — API server & コンソールアクセス
      │    └─ virt-controller — VMI ライフサイクル & スケジューリング
      │         ├─ Worker Node 1
      │         │    ├─ virt-handler (DaemonSet)
      │         │    └─ virt-launcher Pod
      │         │         ├─ libvirtd (session mode)
      │         │         └─ QEMU/KVM
      │         └─ Worker Node N
      │              ├─ virt-handler (DaemonSet)
      │              └─ virt-launcher Pod
      │                   ├─ libvirtd (session mode)
      │                   └─ QEMU/KVM
      ├─ CDI Operator        — VM イメージ インポート/アップロード/クローン
      ├─ SSP Operator        — テンプレート & ブートソース
      └─ Network Addons Op   — Multus CNI セカンダリーネットワーク

Operator (openshift-cnv namespace)

HyperConverged カスタムリソース (CR) は、スタック全体に対する単一のエントリーポイントです。1 つの HyperConverged CR を作成すると、4 つのサブ Operator のデプロイがトリガーされます。

Operator 役割

KubeVirt Operator

コア仮想化。virt-api、virt-controller、virt-handler をデプロイして管理します。

CDI Operator

Containerized Data Importer。VM イメージのインポート、アップロード、PersistentVolumeClaim へのクローン作成を処理します。

SSP Operator

スケジューリング、スケール、パフォーマンス。VM テンプレート、デフォルトのブートソース、テンプレートの検証をデプロイします。

Network Addons Operator

Multus CNI 経由でのセカンダリーネットワークサポートのためのネットワークコンポーネントをデプロイします。

コントロールプレーン

KubeVirt Operator は、非特権 Pod として実行される 2 つのクラスターレベルコンポーネントを作成します。

  • virt-api — VM API リクエストを検証し、コンソール/VNC アクセスを提供する Kubernetes API 拡張機能。

  • virt-controller — VirtualMachineInstance (VMI) オブジェクトを監視し、VM スケジューリング用の Pod を作成し、VM ライフサイクルの状態遷移を管理します。

ノードレベルのコンポーネント

virt-handler は、VM をホスト可能なすべてのノードで DaemonSet として実行されます。昇格された特権で動作し、デバイスの挿入、ネットワークブリッジの設定、VMI 状態のリコンサイルなどのホストレベルのセットアップを実行します。

VM ごとのコンポーネント

各仮想マシンは、専用の virt-launcher Pod 内で実行されます。この Pod には以下が含まれます。

  • セッションモードで実行される libvirtd (root 権限なし、VM ごとに分離)

  • ハードウェアアクセラレーションによる仮想化のための QEMU/KVM

このアーキテクチャーにより、VM プロセスが相互に分離され、デフォルトで非特権ワークロードとして実行されることが保証されます。

VM 実行フロー、ストレージ、ネットワークモデル、従来のハイパーバイザーとの比較など、より広範なアーキテクチャーの概要については、OpenShift Virtualization アーキテクチャの概要 を参照してください。

前提条件

  • OpenShift 4.18+: サポートされているプラットフォーム上でインストールおよび実行されていること

  • クラスター管理者権限: Operator のインストールおよびクラスターリソースの設定に必要

検証済みバージョン:

OpenShift 4.18, 4.19, 4.20, 4.21

ハードウェアおよびソフトウェアの要件

OpenShift Virtualization をインストールする前に、クラスターがハードウェア、オペレーティングシステム、ストレージ、ネットワークの要件を満たしていることを確認してください。

CPU 仕様、サポート対象プラットフォーム、ストレージに関する考慮事項、リソースオーバーヘッドなどの詳細な要件については、OpenShift Virtualization 用のクラスターの準備を参照してください。

ストレージ設定については、 Operator のインストール完了後に デフォルト Storage Class の設定 を参照してください。

Web コンソールを使用したインストール

Web コンソールを使用すると、OpenShift Virtualization のインストールをガイド付きで実行できます。

ステップ 1: OperatorHub へのアクセス

  1. cluster-admin 権限を持つユーザーとして OpenShift Web コンソールにログインします。

  2. Operators → OperatorHub に移動します。

  3. Filter by keyword フィールドに Virtualization と入力します。

ステップ 2: Operator のインストール

  1. Red Hat ソースラベルが付いた OpenShift Virtualization タイルを選択します。

  2. Operator 情報を確認し、Install をクリックします。

  3. Install Operator ページで、デフォルト設定のまま Install をクリックします。

手動承認 (Manual approval) も利用可能ですが、サポートされていないバージョンの組み合わせを実行するリスクがあるため推奨されません。影響を完全に理解している場合にのみ、Manual を選択してください。

  1. Operator のインストールが完了するまで待ちます。

ステップ 3: HyperConverged リソースの作成

  1. Operator のインストールが完了したら、Create HyperConverged をクリックします。

  2. デフォルト設定のまま、一番下までスクロールします。

  3. Create をクリックして、OpenShift Virtualization をデプロイします。

ステップ 4: インストールの確認

すべての条件が成功と報告されるまで待ちます。HyperConverged リソースのステータスでデプロイの進行状況を確認できます。

完了すると、 Operators リストにインストール済みとして表示されます。

コマンドラインを使用したインストール

自動デプロイや Web コンソールにアクセスできない環境では、CLI によるインストール方法を使用します。

ステップ 1: Namespace、 OperatorGroup、Subscription の作成

必要なすべてのリソースを含む単一のマニフェストファイルを作成します。

oc apply -f - <<EOF
apiVersion: v1
kind: Namespace
metadata:
  name: openshift-cnv
---
apiVersion: operators.coreos.com/v1
kind: OperatorGroup
metadata:
  name: kubevirt-hyperconverged-group
  namespace: openshift-cnv
spec:
  targetNamespaces:
  - openshift-cnv
---
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: hco-operatorhub
  namespace: openshift-cnv
spec:
  source: redhat-operators
  sourceNamespace: openshift-marketplace
  name: kubevirt-hyperconverged
  channel: stable
  installPlanApproval: Automatic
EOF

ステップ 2: Operator インストールの確認

Operator がインストールされるのを待ち、ステータスを確認します。

# CSVのステータスが Succeeded になるまで監視
oc get csv -n openshift-cnv -w

インストール完了時に想定される出力:

NAME                                       DISPLAY                    VERSION   REPLACES                                   PHASE
kubevirt-hyperconverged-operator.v4.20.3   OpenShift Virtualization   4.20.3    kubevirt-hyperconverged-operator.v4.20.1   Succeeded

Succeeded と表示されたら Ctrl+C を押して監視を停止します。

ステップ 3: HyperConverged リソースの作成

HyperConverged カスタムリソースをデプロイして、インストールを完了します。

oc apply -f - <<EOF
apiVersion: hco.kubevirt.io/v1beta1
kind: HyperConverged
metadata:
  name: kubevirt-hyperconverged
  namespace: openshift-cnv
spec:
EOF
上記の最小限の HyperConverged スペックは、すべてのデフォルト設定を使用します。高度な設定オプションについては、https://docs.openshift.com/container-platform/latest/virt/install/installing-virt.html#virt-customizing-storage-profile_installing-virt[公式ドキュメント,window=_blank] を参照してください。

ステップ 4: インストール完了の待機

HyperConverged リソースが使用可能になるまで待ちます。

oc wait hyperconverged kubevirt-hyperconverged -n openshift-cnv --for=condition=Available --timeout=15m

インストールには通常 5〜10 分かかります。

ステップ 5: インストールの確認

すべての条件が正常であることを確認します。

oc get hyperconverged kubevirt-hyperconverged -n openshift-cnv -o jsonpath='{range .status.conditions[*]}{.type}: {.status}{"\n"}{end}'

インストール完了時の想定される出力:

ReconcileComplete: True
Available: True
Progressing: False
Degraded: False
Upgradeable: True

インストール後の検証チェックリスト

インストール (Web コンソールまたは CLI 経由) の完了後、デプロイが正常であることを確認します。

Pod ステータスの確認

openshift-cnv namespace 内のすべての Pod が Running または Completed 状態である必要があります。

oc get pods -n openshift-cnv

HyperConverged の Condition の確認

すべての Condition が正常な状態を報告している必要があります。

oc get hyperconverged kubevirt-hyperconverged -n openshift-cnv -o jsonpath='{range .status.conditions[*]}{.type}: {.status}{"\n"}{end}'

想定される出力:

ReconcileComplete: True
Available: True
Progressing: False
Degraded: False
Upgradeable: True

ブートソース DataSource の確認

サポートされているオペレーティングシステムのデフォルトブートソースが利用可能である必要があります。

oc get datasources -n openshift-virtualization-os-images

Ready Condition の RHEL、Fedora、CentOS、Windows ブートイメージのエントリが表示されるはずです。

デフォルト StorageClass の確認

VM ディスクのプロビジョニング用にデフォルト StorageClass が設定されている必要があります。

oc get storageclass

(default) とマークされている StorageClass を探します。設定されていない場合は、VM を作成する前に デフォルト StorageClass の設定 を参照してください。

OpenShift Virtualization のアンインストール

OpenShift Virtualization をクラスターから削除する必要がある場合は、以下の手順を順番に実行してください。アンインストールプロセスでは、すべての仮想化コンポーネントが安全に停止されるため数分かかります。

Operator のサブスクリプションを削除するだけでは、デプロイされたリソースは削除されません。すべてのコンポーネントを適切にクリーンアップするには、まず HyperConverged リソースを削除する必要があります。

ステップ 1: すべての仮想マシンの削除

アンインストール前に、すべての VM が停止および削除されていることを確認してください。

# すべての namespace の VM を一覧表示する
oc get vm -A

# VM を削除する (namespace ごとに繰り返し)
oc delete vm --all -n <namespace>
実行中の VM は、アンインストール中に強制終了されます。

ステップ 2: HyperConverged リソースの削除

このステップで、すべての OpenShift Virtualization コンポーネントが削除されます。

oc delete hyperconverged kubevirt-hyperconverged -n openshift-cnv

クリーンアップの進行状況を監視します。

# Pod が終了するのを見守ってください（5〜10分かかる場合があります）
oc get pods -n openshift-cnv -w

すべての Pod が終了するまで待機してから次に進みます。

ステップ 3: Operator のサブスクリプションと CSV の削除

# subscription を削除
oc delete subscription hco-operatorhub -n openshift-cnv

# ClusterServiceVersion を削除
oc delete csv -n openshift-cnv -l operators.coreos.com/kubevirt-hyperconverged.openshift-cnv

ステップ 4: Namespace の削除 (オプション)

完全にクリーンアップするために、Namespace を削除します。

oc delete namespace openshift-cnv

ステップ 5: クリーンアップの確認

すべてのリソースが削除されたことを確認します。

# 空、または "No resources found" が返される必要があります。
oc get pods -n openshift-cnv
oc get csv -n openshift-cnv

まとめ

OpenShift Virtualization のインストールと設定が完了しました。これで、クラスター上でコンテナワークロードと並行して仮想マシンを実行できるようになりました。
