VirtIO ドライバーを使用した Windows VM のデプロイ

概要

このチュートリアルでは、最適なパフォーマンスを得るために、VirtIO ドライバーを使用して OpenShift Virtualization 上に Windows 仮想マシン (VM) をデプロイする方法を説明します。VirtIO ドライバーは、ネットワーク、ストレージ、およびその他の重要な VM コンポーネントに対して準仮想化 I/O 操作を有効にすることで、エミュレートされたハードウェアと比較して大幅なパフォーマンス向上を実現します。

Windows VM を作成し、Windows のインストールプロセス中に VirtIO ドライバーをインストールして、OpenShift Virtualization との統合を強化するためにゲストエージェントを構成します。

前提条件

  • OpenShift 4.18+ (OpenShift Virtualization Operator がインストール済みであること)

  • CLI ツール: oc および virtctl がインストールされていること

  • Windows インストール ISO (Windows 10/11 または Server 2019/2022)

  • VirtIO ドライバー ISO (Red Hat カスタマーポータルまたは Fedora プロジェクトから入手)

  • 有効な Windows ライセンスおよびプロダクトキー

  • クラスターリソース: 4GB 以上の RAM、60GB 以上の利用可能なストレージ

検証済みバージョン:

OpenShift 4.20, 4.21

ステップ 1: VirtIO ドライバーのダウンロードとアップロード

Fedora プロジェクトから VirtIO ドライバーの ISO をダウンロードします。

curl -L -O https://fedorapeople.org/groups/virt/virtio-win/direct-downloads/stable-virtio/virtio-win.iso

VirtIO ドライバー ISO 用の DataVolume を作成します。

virtio-drivers-dv.yaml をダウンロード

oc apply -f - <<EOF
apiVersion: cdi.kubevirt.io/v1beta1
kind: DataVolume
metadata:
  name: virtio-drivers-iso
  annotations:
    cdi.kubevirt.io/storage.bind.immediate.requested: "true"
spec:
  storage:
    resources:
      requests:
        storage: 1Gi
    accessModes:
      - ReadWriteOnce
  source:
    upload: {}
EOF

VirtIO ドライバーの ISO をアップロードします。

virtctl image-upload dv virtio-drivers-iso --image-path=virtio-win.iso --insecure
CDI アップロードプロキシが自己署名証明書を使用する開発環境では、--insecure フラグが必要になることがよくあります。

ステップ 2: Windows インストール ISO のアップロード

Windows インストール ISO 用の DataVolume を作成します。

oc apply -f - <<EOF
apiVersion: cdi.kubevirt.io/v1beta1
kind: DataVolume
metadata:
  name: windows-installation-iso
  annotations:
    cdi.kubevirt.io/storage.bind.immediate.requested: "true"
spec:
  storage:
    resources:
      requests:
        storage: 6Gi
    accessModes:
      - ReadWriteOnce
  source:
    upload: {}
EOF

Windows インストール ISO をアップロードします (windows.iso は実際の ISO ファイル名に置き換えてください) 。

virtctl image-upload dv windows-installation-iso --image-path=windows.iso --insecure

ステップ 3: VirtIO 構成を使用した Windows VM の作成

VirtIO デバイスと適切なブート順序を使用して Windows 仮想マシンを作成します。

windows-vm-virtio.yaml をダウンロード

oc apply -f - <<EOF
apiVersion: kubevirt.io/v1
kind: VirtualMachine
metadata:
  name: windows-vm-virtio
  labels:
    app: windows-vm-virtio
spec:
  runStrategy: Always
  template:
    metadata:
      labels:
        kubevirt.io/size: medium
        kubevirt.io/domain: windows-vm-virtio
        vm.kubevirt.io/name: windows-vm-virtio
    spec:
      domain:
        cpu:
          cores: 2
          sockets: 1
          threads: 2
        resources:
          requests:
            memory: 4Gi
        devices:
          disks:
            - name: rootdisk
              disk:
                bus: virtio
              bootOrder: 2
            - name: windows-installation-iso
              cdrom:
                bus: sata
              bootOrder: 1
            - name: virtio-drivers-iso
              cdrom:
                bus: sata
          interfaces:
            - name: default
              masquerade: {}
              model: virtio
          tpm: {}
          rng: {}
        clock:
          utc: {}
          timer:
            hpet:
              present: false
            pit:
              tickPolicy: delay
            rtc:
              tickPolicy: catchup
            hyperv: {}
        features:
          acpi: {}
          apic: {}
          hyperv:
            relaxed: {}
            vapic: {}
            spinlocks:
              spinlocks: 8191
            vpindex: {}
            runtime: {}
            synic: {}
            stimer: {}
            reset: {}
            frequencies: {}
            reenlightenment: {}
            tlbflush: {}
            ipi: {}
          smm:
            enabled: true
        firmware:
          bootloader:
            efi:
              secureBoot: true
      networks:
        - name: default
          pod: {}
      volumes:
        - name: rootdisk
          dataVolume:
            name: windows-vm-virtio-rootdisk
        - name: windows-installation-iso
          dataVolume:
            name: windows-installation-iso
        - name: virtio-drivers-iso
          dataVolume:
            name: virtio-drivers-iso
  dataVolumeTemplates:
    - metadata:
        name: windows-vm-virtio-rootdisk
        annotations:
          cdi.kubevirt.io/storage.bind.immediate.requested: "true"
      spec:
        storage:
          resources:
            requests:
              storage: 60Gi
          accessModes:
            - ReadWriteOnce
        source:
          blank: {}
EOF

VM が起動するのを待ちます。

oc get vm windows-vm-virtio -w

STATUS=Running かつ READY=True になったら、次に進みます。Ctrl+C を押して監視を終了します。

ステップ 4: VirtIO ストレージドライバーを使用した Windows のインストール

VM コンソールにアクセスして Windows のインストールを開始します。

virtctl vnc windows-vm-virtio

または、OpenShift Web コンソールを使用します: Virtualization → VirtualMachines → windows-vm-virtio → Console タブ。

  1. Windows のインストールを開始:

    VM が起動すると、最初に「No bootable device found」というメッセージが表示される場合があります。これは通常の動作です。UEFI ブートメニューを操作する必要があります。

    • UEFI メニューが表示されるのを待つか、プロンプトが表示されたら何かキーを押して「boot from other media or DVD」を実行します。

    • ブートメニューに移動し、「Boot from DVD/CD」を選択します。

    • 利用可能な最初のオプション (通常は Windows ISO) を選択します。

    • Windows のインストールが開始されます。初期セットアップ画面を進めてください。

  2. VirtIO ストレージドライバーの読み込み: 「Windows のインストール場所を選択してください」画面に到達したら、以下を実行します。

    • ドライバーの読み込みをクリックします。

    • VirtIO ドライバー CD (通常は D: または E: ドライブ) を参照します。

    • viostor{windows-version}\amd64\ フォルダーに移動します。

    • Windows Server 2022 の場合: viostor\2k22\amd64\

    • Windows 11 の場合: viostor\w11\amd64\

    • Red Hat VirtIO SCSI Controller を選択し、次へをクリックします。

  3. インストールディスクの選択: インストール対象のリストに VirtIO ディスクが表示されます。これを選択して Windows のインストールを続行します。

  4. インストールの完了: 標準の Windows セットアップ手順に従います。

ステップ 5: 残りの VirtIO ドライバーのインストール

Windows のインストールが完了し、デスクトップに到達したら、以下を実行します。

  1. デバイスマネージャーを開く: PCを右クリック → プロパティ → デバイスマネージャー

  2. ネットワークドライバーのインストール:

    • 警告アイコンが付いたネットワークデバイスを右クリックします。

    • ドライバーの更新 → コンピューターを参照してドライバーを検索を選択します。

    • VirtIO CD 内の NetKVM{windows-version}\amd64\ に移動します。

    • インストールを完了します。

  3. 追加ドライバーのインストール:

    • Balloon ドライバー: 「PCI デバイス」を更新 → Balloon{windows-version}\amd64\

    • シリアルドライバー: 「PCI シンプル通信コントローラー」を更新 → vioserial{windows-version}\amd64\

    • 入力ドライバー: 「PCI 入力デバイス」を更新 → vioinput{windows-version}\amd64\

  4. QEMU guest agent のインストール:

    VirtIO ドライバー CD から guest-agent\qemu-ga-x86_64.msi を実行し、インストールウィザードに従います。

ステップ 6: インストールの確認

すべての VirtIO ドライバーが正しくインストールされていることを確認します。

  1. デバイスマネージャーの確認: すべてのデバイスに警告アイコンが表示されていないことを確認します。

  2. ゲストエージェントの確認: サービス (services.msc) を開き、QEMU Guest Agent が実行中であることを確認します。

  3. 統合のテスト: OpenShift から、ゲストエージェントの通信を確認します。

oc get vmi windows-vm-virtio -o jsonpath='{.status.guestOSInfo}'

VM のパフォーマンスメトリックを確認します。

oc get vmi windows-vm-virtio -o jsonpath='{.status.interfaces[0].ipAddress}'

VirtIO ドライバーの利点

VirtIO ドライバーをインストールすると、Windows VM で以下の利点が得られます。

コンポーネント パフォーマンス向上

ネットワーク (NetKVM)

ネットワークスループットが最大 10 倍向上

ストレージ (viostor)

ストレージのレイテンシが大幅に削減され、IOPS が向上

バルーン (vioser)

動的なメモリ管理とリソース利用率の向上

ゲストエージェント

統合の強化、正常なシャットダウン、監視機能

トラブルシューティング

一般的な問題

問題 原因 解決策

インストール中の TPM 2.0 エラー

TPM デバイスの不足

VM テンプレートには Windows 11 の要件を満たす TPM サポートが含まれています

起動デバイスが見つからない

ブート順序の誤り

Windows ISO が bootOrder: 1 で、ルートディスクが bootOrder: 2 であることを確認してください

インストール中にディスクが表示されない

VirtIO ストレージドライバーが読み込まれていない

インストールディスクを選択する前に viostor ドライバーを読み込んでください

ネットワークパフォーマンスが低い

NetKVM ドライバーの不足

Windows インストール後にデバイスマネージャーからネットワークドライバーをインストールしてください

アップロードの問題

ISO アップロード中に TLS 証明書エラーが発生する場合:

# 開発環境では --insecure フラグを使用します
virtctl image-upload dv <datavolume-name> --image-path=<iso-file> --insecure

クリーンアップ

このチュートリアルで作成したすべてのリソースを削除します。

oc delete vm windows-vm-virtio
oc delete dv windows-installation-iso virtio-drivers-iso

まとめ

このチュートリアルでは、以下の方法を学びました。

  • DataVolume を使用して VirtIO ドライバーと Windows インストール ISO をアップロードする

  • VirtIO デバイスと適切なハードウェア構成を備えた Windows VM を作成する

  • 最適なパフォーマンスを得るために、Windows インストール中に VirtIO ストレージドライバーをインストールする

  • インストール後に残りの VirtIO ドライバーと QEMU guest agent を構成する

  • ドライバーの適切なインストールと、OpenShift Virtualization との VM 統合を確認する

  • 一般的なインストール問題のトラブルシューティングを行う

これで、Windows VM は完全な VirtIO ドライバーサポートと OpenShift Virtualization との統合を備え、エンタープライズグレードのパフォーマンスを発揮できるようになりました。
